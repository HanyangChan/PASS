# PASS mobile

Expo / React Native iOS·Android 앱. 화면 이동은 Expo Router와 공유 상태 Provider로 구성했습니다. 모바일 소스는 `mobile/`, 기존 웹 앱과 서버는 저장소 루트에 있습니다.

```sh
cd mobile
npm ci
npm start
```

음성 입력은 네이티브 모듈 `expo-speech-recognition`을 사용하므로 개발 빌드(`npx expo run:ios` / `npx expo run:android`, 또는 EAS development 빌드)에서 실행해야 합니다. Expo Go에는 이 모듈이 포함되어 있지 않아 동작을 기대할 수 없으며, Expo Go 동작은 확인하지 않았습니다. `npm run ios`는 Xcode/iOS Simulator, `npm run android`는 Android SDK/에뮬레이터가 필요합니다. Node.js 22.13 이상, Expo SDK 57을 사용합니다. 앱스토어 서명·식별자·EAS 프로젝트는 아직 설정하지 않았고 기본 Expo 아이콘은 임시입니다.

## 구현

첨부된 `E-commerce AI Shopping Assistant (Community).zip`의 홈·대화·수령인별 랭킹·상품 상세·하단 탭 구조를 React Native로 옮겼습니다. 원본 ZIP은 버전 3 수준의 소스로, 마이는 자리 표시자이며 음성·첨부파일·가짜 로그인·고정 점수 추천 기능은 포함되어 있지 않습니다.

- 홈: 8개 선물 카테고리, 인기 상품, 실제로 열어본 상품의 최근 기록.
- AI 추천: 기존 `lib/single-gift.mjs`/`engine.mjs`의 조건 추출과 추천. 고정 모의 응답 대신 실제 기존 로직으로 처리하며, 규칙 기반 식품 선물 범위입니다.
- 추천 결과: 현재 추천 카드, `lib/counterfactual.mjs`의 예산만 바꾼 재계산 결과와 명시적 적용. 비교 열람만으로 현재 예산은 변하지 않습니다.
- 랭킹: 원본의 전체·부모님·친구·직장동료별 10개 데모 목록, 이름 검색, 상품군 필터, 가격 정렬.
- 상세: 원본 이미지·상품 설명·전체 화면 상세, 공유, 찜. 선물하기는 구매 준비 중 안내를 표시합니다.
- 마이: 찜/최근 본 선물과 도움말. 실제 계정이나 구매 이력을 꾸며 표시하지 않습니다.
- 설문: 모바일 진입 경로 없음. 웹 `/study`도 홈으로 리다이렉트하며 설문 코드는 보존합니다.

## 디자인과 데이터

Make의 화면 구조와 제공된 상품 사진 URL/Lucide 아이콘을 사용하고, 두 번째 Figma `cajZ71MOH37gT4ltwQlvbb / 36:1701`에서 확보한 Noto Sans KR·색상·세그먼트·칩·랭킹 카드 스타일로 통일했습니다. Make 원본의 Noto Serif KR는 적용하지 않았습니다. UI 토큰과 카드/칩은 `src/theme.ts`, `src/components.tsx`에서 재사용합니다.

`src/make-data.json`은 첨부 소스의 데이터 리터럴에서 추출한 스냅샷입니다. 상품·가격·평점·인기 수치·배송 정책은 모두 프로토타입용이며 실제 판매나 검증된 상거래 정보가 아닙니다. 랭킹의 다양한 상품군과 기존 대화의 30개 식품 카탈로그는 구분됩니다. 원본 상품 사진은 제공된 Unsplash URL에서 로드하므로 인터넷이 필요합니다. 원본의 일부 사진 URL은 로드되지 않아 사진 로드 실패 안내를 표시합니다. SVG 7개와 한국어 폰트는 로컬에 포함됩니다. 저작권 출처는 `ATTRIBUTIONS.md`에 보존했습니다.

찜과 최근 기록(최대 20개)은 AsyncStorage에 저장하고, 대화는 메모리에만 유지합니다. 모바일은 기존 Gemini 서버를 호출하지 않습니다. 서버는 같은 origin 요청만 허용하므로 모바일 API 인증/계약을 갖춘 후 LLM을 연결해야 합니다. Gemini API 키는 앱에 포함하지 않았습니다.

### 채팅 프로토타입 조작

- `음성 입력`: 말하기 시작 → 마이크·음성 인식 권한 요청 → 한국어(`ko-KR`) 인식 중 실시간 글자 표시 → 말하기 완료 → 인식 결과 확인·수정 → 입력창 적용. 자동 전송하지 않으며 보내기 버튼을 눌러야 추천에 반영합니다. iOS·Android 앱은 음성을 외부 서버로 보내지 않도록 기기 전용 인식(`requiresOnDeviceRecognition`)만 사용하고, 마이크 권한만 요청합니다. 기기 전용 인식을 지원하지 않는 기기(라이브러리 문서 기준 Android 13 미만 등)에서는 음성 입력 대신 글 입력을 안내합니다. Android는 한국어 오프라인 모델이 없으면 "한국어 음성 인식 모델 받기" 버튼을 표시합니다. 브라우저에는 기기 전용 모드가 없어 웹 데모는 브라우저 음성 인식을 사용하며, 브라우저에 따라(Chrome 등) 음성이 인식 서비스 서버로 전송될 수 있습니다. 권한 거부·말소리 없음·미지원 언어 등 실패 시 안내를 표시하고 같은 창에서 글로 입력할 수 있습니다. 실기기 동작과 기기 전용 인식의 한국어 정확도는 미검증입니다.
- `현재 조건 확인`: 대화의 받는 분, 예산, 배송비, 선호·제외 조건, 브랜드, 수령일, 포장을 확인·수정합니다. 취소는 기존 조건을 보존하고 적용은 추천 결과를 갱신합니다.
- 새 Figma 파일은 읽기 권한이 확보되지 않아 기존 디자인 토큰으로 구성한 임시 화면입니다.

### Vercel 데모 배포

저장소 루트의 `vercel.json`이 모바일 앱의 웹 버전을 빌드하도록 설정합니다. Vercel에 PASS 저장소를 가져올 때 Root Directory는 저장소 루트(`.`)로 유지합니다. `mobile` 밖에 있는 추천 엔진 파일도 함께 빌드해야 합니다.

- Framework Preset: Other
- Install Command: `npm --prefix mobile ci`
- Build Command: `npm --prefix mobile run build:web`
- Output Directory: `mobile/dist`
- 환경변수: 데모에 필요 없음

GitHub 배포는 최신 변경이 들어 있는 브랜치를 먼저 push한 뒤 해당 브랜치를 연결해야 합니다. 웹 정적 페이지이므로 모든 경로를 홈으로 강제하는 SPA rewrite는 추가하지 않습니다. `cleanUrls`로 `/chat`, `/ranking` 등의 직접 접근을 처리합니다.

GitHub 연결 없이 CLI로 배포하려면 저장소 루트에서 `npx vercel@latest`를 실행하고 로그인/프로젝트 설정을 완료합니다. 첫 명령은 미리보기 배포이며, 공개 운영 주소를 갱신할 때는 `npx vercel@latest --prod`를 실행합니다.

Vercel에는 브라우저 데모가 배포됩니다. 앱스토어용 iOS/Android 설치 파일 배포는 별도의 EAS 빌드로 진행합니다.

### 음성 입력 안전성 수정

- `npm ci`의 postinstall은 `expo-speech-recognition` 57.1.0의 iOS에서 실제 요청 언어의 기기 전용 지원을 녹음 전에 검사하고 요청에 기기 전용 플래그를 적용합니다. 요청 언어가 기기 전용 인식을 지원하지 않으면 서버 인식으로 전환하지 않고 실패합니다. 라이브러리 버전 또는 소스가 바뀌면 설치를 중단하므로 업그레이드 시 패치를 재검증해야 합니다. 설치 스크립트를 생략하지 마세요.
- 이 변경은 네이티브 코드이므로 기존 개발 빌드를 다시 빌드해야 합니다. OTA 업데이트만으로 적용되지 않습니다.
- 음성 입력을 준비하는 동안 중복 시작을 막고, 창 닫기·재열기·화면 종료 시 이전 권한/언어 조회 요청을 무효화합니다. Android 모델 조회는 실제 기기 전용 인식 서비스를 사용합니다.
- `npm run test:voice`로 세션 취소·중복 시작·iOS 패치 보호를 검증합니다. 실기기에서 한국어 지원/미지원, 권한 거부 및 취소 후 재열기 동작도 확인해야 합니다.

### 서비스 계층

- `src/domain.ts`: 선물·추천 조건·대화 세션·메시지·기기 기록 공통 타입.
- `src/services/chatService.ts`: 게스트 대화, 조건 수정, 추천/예산 비교, 화면용 상품 변환. 공통 추천 엔진과 제품 데이터를 화면에서 직접 호출하지 않습니다.
- `src/services/giftRepository.ts`: 기존 v1 찜·최근 기록 복원과 순차 저장. 한 기록의 읽기 실패가 다른 기록 복원을 막지 않으며 저장 실패 후 다음 저장은 계속됩니다.
- `src/services/localServices.ts`: 제품 데이터와 AsyncStorage를 서비스에 연결하는 구성 지점. 추천은 로컬 엔진입니다. 게스트 기록은 AsyncStorage, 로그인 계정 기록은 cloudRecords를 통해 Supabase에 연결합니다.

`npm run test:services`는 Node 22.13 이상에서 서비스 회귀 테스트를 실행합니다. Supabase 스키마/RLS·인증·계정 기록 저장이 연결되어 있습니다. 다음 구현 단계는 서버 추천 API입니다. 서버 호출은 비동기 상태·오류 처리 및 JWT 검증을 별도로 구현해야 합니다.

### Supabase 로그인

1. `.env.example`을 `.env.local`로 복사하고 프로젝트 URL과 **Publishable key**를 입력합니다. 관리자 키나 service_role 키는 앱에 사용하지 않습니다. Vercel에서는 동일한 `EXPO_PUBLIC_` 환경 변수를 빌드 환경에 설정해야 합니다.
2. `npm ci` 후 `npm start` 또는 `npm run build:web`로 실행합니다. 설정이 없으면 게스트 추천은 유지되고 로그인 버튼은 비활성화됩니다. 임의 비밀번호로 로그인한 것처럼 표시하지 않습니다.
3. Supabase Auth에서 이메일 로그인을 활성화하고 Site URL을 실제 웹 데모 URL로 설정합니다. 회원가입 후 메일의 인증 링크를 확인하고 앱으로 돌아와 이메일/비밀번호로 로그인합니다. OAuth·앱 인증 딥링크·비밀번호 재설정은 이번 단계에 포함하지 않습니다.
4. 네이티브 세션은 SecureStore에 작은 조각으로 저장합니다. 웹은 Supabase SDK의 브라우저 저장소를 사용합니다. SecureStore와 Expo Crypto를 추가했으므로 개발 빌드를 다시 만들어야 합니다.
5. `npm run test`와 `npm run test:db`로 인증 서비스·세션 저장·RLS를 검사합니다. 실제 Supabase 테스트 계정으로 웹 로그인·새로고침·재로그인과 기록 복원을 확인했습니다. iOS/Android 실기기 동작은 별도로 확인해야 합니다.

### 계정 기록 저장과 복원

- 로그인 사용자의 찜·최근 본 선물은 `gift_records`, 대화와 조건은 `conversations` / `messages`에 저장합니다. 앱을 다시 열면 마지막으로 저장을 완료한 대화를 복원합니다. 이전 대화는 DB에 보존되지만 대화 목록 화면은 아직 없습니다.
- 게스트 찜·최근 기록은 기존 v1 기기 저장소를 그대로 사용합니다. 로그인할 때 게스트 기록을 계정으로 자동 업로드하지 않습니다. 계정 전환 시 화면 상태를 다시 만들고, 종료된 계정의 대기 중 저장 요청은 취소합니다.
- `cloudRecords.ts`는 고정 소유자 ID와 RLS로 접근하고 변경된 항목만 upsert합니다. 삭제는 이 기기에서 실제로 제거한 찜/최근 항목에만 적용해 다른 기기의 미조회 항목을 보존합니다. 기록 조회는 페이지를 나누어 서버의 기본 행 수 제한을 넘는 데이터도 복원합니다.
- 대화는 재시도에도 같은 UUID를 사용합니다. 메시지 저장 이후 `conditions._pass`의 버전·순서 ID·이슈·완료 표시를 갱신합니다. 읽을 때 완료된 대화의 확정된 메시지만 복원하므로 중간 실패로 생성된 메시지가 화면 기록에 섞이지 않습니다.
- 서버 기록을 못 읽으면 저장을 시작하지 않고 다시 불러오기/로그아웃을 표시합니다. 저장 실패는 현재 화면에 유지하고 다시 시도 버튼을 표시합니다. 실패한 변경을 앱 종료 후 재전송하는 영속 오프라인 큐는 아직 없습니다.
- 동시 편집 시 같은 선물 항목 및 같은 대화는 마지막 저장이 우선합니다. 실시간 기기 간 갱신·대화 충돌 병합은 아직 없으며 재진입/재로그인 때 복원합니다. 선물 준비 체험 기록은 사용자별 메모리이며 주문/결제 기록으로 저장하지 않습니다.

검증: 실제 테스트 계정에서 대화·예산·수신자와 찜/최근 기록의 새로고침 및 재로그인 복원, 로그아웃 시 게스트 기록 분리를 확인했습니다. 인증/음성/서비스 27개와 DB RLS 4개, 공통 엔진 66개 회귀 테스트가 통과했습니다.
