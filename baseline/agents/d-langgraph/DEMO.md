# 기말 데모 대본 (C + D 에이전트 모드)

약 4분. 실제 앱 웹 화면에서 로그인한 상태로 진행한다.

## 준비 (데모 전날)

1. API: `api/wrangler.jsonc`의 `AGENTS_MODE`를 `"on"`으로 바꾸고 `npm --prefix api run deploy`. Gemini 키는 기존 Cloudflare secret을 그대로 쓴다. 모델은 `AGENTS_MODEL`(기본 `gemini-3.5-flash-lite`).
2. 앱: `EXPO_PUBLIC_AGENTS_MODE=on`으로 웹을 빌드해 배포하거나, 로컬에서 실행한다.
3. 데모 계정의 기기 기록을 미리 만든다.
   - 캘린더: "엄마 생일"을 데모 당일 기준 10일 뒤로 등록
   - 마이 → 기억과 구매 이력: 어머니에게 뷰티 상품 "만족", 과자 상품 "불만족" 등록
4. 리허설 후 `AGENTS_MODE`를 다시 `"off"`로 돌려야 할 경우를 대비해, 배포 커밋을 메모해 둔다.

## 진행

| 순서 | 입력·동작 | 보여줄 것 | 말할 것 |
| --- | --- | --- | --- |
| 1 | "엄마 선물 5만원 이하 배송비 포함" | 추천 카드 아래 의견 패널: 명절(엄마 생일 D-10 · 캘린더), 소비(예전 선물 범위 · 구매 기록), 취향(만족한 뷰티 반영 · 추천에 반영), 관계(부모님 무난 품목) | 네 에이전트가 각자 근거를 들고 의견을 냅니다. 상품은 공통 엔진만 고릅니다. |
| 2 | 취향 스위치 끄기 | 추천이 바로 바뀜, 취향 의견이 회색 | 끄면 LLM 없이 즉시 재계산합니다. 사용자가 에이전트를 통제합니다. |
| 3 | "나는 과자 좋아하는데 엄마는 견과류 알레르기가 있어" | 이해한 조건: "과자·간식 선호 · 나 · 미반영", "견과류 알레르기 · 어머니" | 누구의 조건인지 구분합니다. 기존 규칙 경로는 과자를 엄마 취향으로 넣었습니다(평가 A의 유출 10건). |
| 4 | 기억 카드 → "기억하기" | 마이의 기억 목록에 견과류 알레르기 | 대화에서 나온 사실도 확인을 받은 뒤에만 저장합니다. |
| 5 | 제안 "11/○○까지 도착하는 상품만 보기" 누르기 | 미리보기의 후보 수, 적용 후 조건 칩에 마감일 | 예산·마감 같은 강한 조건은 사용자가 눌러야 바뀝니다. |
| 6 | "아빠랑 엄마 중에 한 분이 우유 알레르기야" | 추천 대신 질문 "우유 알레르기는 누구에게 해당하나요?" | 안전 관련 조건의 주인이 불분명하면 추측하지 않고 묻습니다. |

## 평가 결과 한 장

`eval/results.md` 표에서 A·C·D 세 줄만 보여준다. 위반 0, 주는 사람 조건 유출 A 10건 → C·D 0건, 숨은 취향 상위 3개 포함률 A 53% → C 80% → D 100%, 기대한 제안 D 100%. D−taste에서 포함률이 80%로 떨어지는 것이 취향 에이전트의 기여다. 합성 시나리오 결과라는 점을 함께 말한다.

## 실패 시 대응

- Gemini가 느리거나 실패하면 앱은 "조금 더 구체적으로 알려주세요" 질문을 보여준다. 4번 발화처럼 규칙으로 처리되는 문장으로 다시 시연한다.
- 서버 응답이 오지 않으면 `AGENTS_MODE` 없이도 기존 경로가 그대로 동작한다.
- 배포나 데모 계정을 쓸 수 없으면 [로컬 E2E](e2e/README.md)로 같은 화면을 노트북에서 시연한다. 2026-11-05에 이 방법으로 위 1~6번을 모두 실제 앱 화면에서 확인했다.
