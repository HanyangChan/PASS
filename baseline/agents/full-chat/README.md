# B안 · 전체 채팅 Agent

로그인한 사용자가 서버 `/api/chat`으로 보내는 모든 발화를 단일 Agent가 처리한다. 인사·명확한 조건 입력·빠른 답장·추천·이유 설명·가상 예산 비교가 모두 첫 LLM 호출을 거친다. 규칙 Router로 우회하지 않으며 B 자체에는 별도의 Planner·Reflection·답변 수정 모델이 없다. C안의 반복 피드백은 인접한 `full-chat-feedback/`에 구현되어 있다.

## 실행

저장소 루트에서 실행한다. 서버 `api/.dev.vars`에 기존 OpenAI 호환 플랫폼 설정과 `LLM_API_KEY`가 필요하다. Gemini 직접 연결은 이 모드에서 지원하지 않는다. `LLM_RESPONSE_FORMAT`은 `json_object` 또는 `text`를 사용한다.

```sh
npm run dev:api:full-chat
```

지속적으로 선택하려면 서버 `api/.dev.vars`의 `CHAT_AGENT=full-chat`을 설정하고 `npm run dev:api`를 실행한다. A안으로 비교 실행하려면 `CHAT_AGENT=a-router npm run dev:api`를 사용한다. 같은 포트 8788을 사용하므로 기존 개발 서버를 종료한 뒤 전환한다. 운영 `wrangler.jsonc`의 기본값은 그대로이며 배포는 별도다.

`GET /health`에서 `agent: full-chat`, `llmMode: agent-loop`를 확인한다. 키가 없거나 공급자 설정이 맞지 않으면 503으로 실패하며 규칙 모드로 대체하지 않는다. A안의 `A_ROUTER_LLM_MODE` 설정은 B안에서 사용하지 않는다.

```sh
npm run test:full-chat
npm --prefix baseline test
npm --prefix api test
npm run demo:full-chat
npm run smoke:full-chat
```

`demo:full-chat`은 모의 모델 결정 + 실제 공통 엔진 실행 예제다. `smoke:full-chat`은 서버 키로 실제 공급자 호출을 하므로 사용량이 발생한다. 합성 카탈로그·합성 세션·인증 모형으로 실제 API 핸들러를 검사하며 실제 로그인·브라우저·운영 DB 검사는 아니다. 키나 내부 추론 원문은 출력하지 않는다.

## 기본 루프

1. 요청의 인증·세션·입력을 서버가 검증한다.
2. 모델에 현재 조건·직전 질문·최근 6개 대화·이번 턴 도구 관찰을 전달한다.
3. 모델이 조건 수정, 상품 검색, 예산 가상 비교, 추천 이유, 확인 질문, 종료 중 하나를 선택한다.
4. 서버가 행동 스키마·인자·실행 한도를 검증하고 공통 코어를 실행한다. 조건 수정 도구는 공통 코어의 필수 정보 확인·추천 결과도 반환한다.
5. 관찰을 모델에 돌려주고 다음 행동을 선택한다. 필수 정보가 빠지면 서버 질문으로 이번 실행을 종료한다.
6. 모델이 선택한 응답 종류에 따라 검증된 엔진 사실이나 대화 템플릿을 표시한다.

LLM이 **흐름과 행동을 선택**한다. 현재 버전의 최종 문장은 자유 생성이 아니라 근거 기반 템플릿이다. 인사·감사·도움말·확인 응답도 모델이 종류를 선택하고 서버가 문장을 렌더링한다. 지원 범위 밖의 대화는 확인 질문으로 반환할 수 있다. 이 구현을 자유 대화 생성 효과 실험으로 해석하지 않는다.

## 실행·상태 계약

- 기본 상한: LLM 6회, 도구 5회, Agent 전체 20초. 전송기의 일시적 5xx 재시도는 호출당 최대 1회이므로 HTTP 시도는 최대 12회다. 전송 개별 제한 18초도 전체 20초 내에서 취소된다. 앱의 25초 요청 제한을 고려한 값이며 실제 네트워크 상황에서 항상 완료를 보장하지 않는다.
- 같은 상태·행동·인자의 반복, 바뀌지 않는 조건 수정의 반복, 결과 없이 종료, 도구 실행 후 일반 인사로 종료는 중단한다. 이미 적용된 조건을 한 번 확인하고 정상 종료하는 것은 허용한다. 별도 재계획·응답 재검토 루프는 없다.
- 조건은 실행 중 복제 세션에만 적용한다. 모델·도구 실패, 취소, 한도 초과, 추가 확인 질문에서는 원래 상태를 보존한다. 필수 정보 질문으로 정상 종료할 때는 검증된 변경을 반환한다.
- 상품·순위·가격·배송비·예산 계산은 공통 `baseline/src/` 코어와 엔진이 처리한다. 이 기능 때문에 공통 엔진이나 기존 A안 폴더를 변경하지 않았다.
- 가상 예산 비교는 실제 예산을 바꾸지 않는다. 기존 알레르겐 제외의 삭제는 명시적 취소 표현 또는 명시적인 조건 편집을 통해서만 허용한다. 신규 자연어 조건의 의미·귀속 판단은 모델의 역할이며 스키마 검증이 의미 정확성을 보장하지 않는다.
- 모델에는 앱에서 지원하지 않는 `quantity`, `same_product`, `budget.scope`를 노출하지 않는다. 단일 선물만 지원하며 여러 선물 요청은 확인 대상이다.
- 향 강도는 측정하지 않는다. `preferences`의 `avoid_fragrance`로 상품명에서 향수·방향제·디퓨저·향초·인센스·에센셜 오일 등을 찾아 제외한다. 무향으로 명시된 제품은 허용하며, 화장품·홈데코 전체를 제외하지 않는다. 일반 조회·예산 비교에도 유지되고 서버는 상품명 기준 안내를 표시한다. 이전 `scent_strength` 한계 코드는 필터가 적용되지 않은 기존 응답과의 호환용이다.
- `어/응/네/그래`는 앞선 예/아니요 제안의 동의로 해석한다. 명시된 사용자 제외 조건은 잘못 작성된 이전 어시스턴트 질문보다 우선하며, 이미 동의한 요청의 재확인과 빈 검색 결과 뒤의 불필요한 질문을 피하도록 행동·검토 프롬프트를 보강했다. 의미 판단은 여전히 모델에 의존하므로 모든 표현에 대한 보장은 아니다.
- 화면 조회·명시적인 조건 편집은 채팅 발화가 아니므로 서버 경로로 처리하고 LLM은 0회다. 게스트·서버 미연결 기기의 로컬 채팅은 이 모드의 범위 밖이다.
- 호스트가 최근 대화·미해결 질문을 보관한다. 새로운 자동 장기 기억·서버 영속 세션·원자적 CAS는 추가하지 않았다. 현재 API는 기존처럼 요청별 무상태 어댑터다.

`routing`은 `agent`, `route`, `llmCalls`, `toolCalls`, `httpAttempts`, `usage`, 행동 이름 목록 `steps`, `stopReason`을 제공한다. 입력 원문·인자·키·내부 추론은 진단에 넣지 않는다. 누락된 공급자 사용량은 0으로 합산하며 실제 과금은 공급자 기록으로 확인한다.

기존 베이스라인 registry의 모든 구현은 규칙 우선 해석기 계약을 전제하므로 B안은 그 registry에 넣지 않았다. 이 폴더의 `createAgent`와 서버 `CHAT_AGENT`가 명시적인 진입점이다.
