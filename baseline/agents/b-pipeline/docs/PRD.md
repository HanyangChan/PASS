# PRD — PASS B 역할 파이프라인: 받는 사람을 기억하는 선물 추천

작성 2026-11-05 · 담당 폴더 `baseline/agents/b-pipeline/` · 구조도 [architecture.png](architecture.png) · 기술 명세 [TRD.md](TRD.md)

## Problem
선물을 고를 때 사용자는 받는 사람의 취향, 알레르기, 작년에 드린 선물, 예산을 매번 처음부터 설명해야 한다. 기존 쇼핑 에이전트(네이버 쇼핑 AI 에이전트, 카카오톡 선물하기, ChatGPT shopping research, Alexa for Shopping)는 추천을 근거와 함께 보여주지만, 다음 세 가지를 하지 않는다.

1. 받는 사람별로 취향을 기억해 다음 방문에 자동으로 반영하는 것
2. "그 기억이 없었다면 무엇이 1위였는지"를 실제로 다시 계산해 보여주는 것
3. 예산을 바꿨을 때 무엇을 얻고 잃는지 보여주되, 비싼 상품을 권하지 않는 것

또한 사용자 피드백에 따르면, 사용자는 긴 설명 글을 읽기 싫어하고 빨리 맞는 상품을 받기를 원한다.

## Users
명절·생일·기념일에 선물을 고르는 20~30대. 받는 사람에 따라 기준이 다르다.

- **가족(부모님):** 취향과 과거 선물을 알고, 마음을 담아 조금 더 쓸 의향이 있다.
- **친구:** 예산이 빠듯하고 가성비를 중시한다. 취향은 대화 중에 처음 말한다.
- **격식 있는 관계(교수님·직장 상사):** 상한을 넘으면 오히려 부담이 된다. 포장과 무난함이 중요하다.

## Scenarios
| # | 사용자·수령인 | 상황 | 이 시나리오로 확인하는 것 |
|---|---|---|---|
| S1 | userA → 부모님 (1회차) | 추석. "엄마는 단 거 싫어하시고 땅콩 알레르기, 아빠는 등산 좋아하셔. 5만 원" | 대화에서 기억 후보 추출, 세션 끝 "기억할까요?" 확인 후 저장 |
| S2 | userA → 부모님 (2회차) | 설날. "부모님 설 선물 추천해줘"만 입력 | 저장된 기억 자동 반영, 반영 한 줄 표시, 작년 선물 표시, 기억 반사실 |
| S3 | userA → 친구 | 생일, 기억 없음, "커피 좋아해, 3만 원" | 기억 없이 대화 정보만으로 추천, 다른 수령인 기억이 섞이지 않음, 아끼기 옵션 |
| S4 | userB → 교수님 | 스승의 날, 3만 원 상한 고정, 격식 포장 | 상한 초과 제안 금지 |
| S5 | userA → 어머니 | 기억과 반대되는 말: "요즘은 단 것도 드셔" | 기억을 덮어쓰지 않고 바꿀지 묻기 |

## Features
### F1. 빠른 첫 추천
수령인과 예산이 정해지면 질문 없이 카드 3개를 먼저 보여준다. 필수 조건이 빠졌을 때만 칩으로 하나를 묻는다. 설명은 카드 다음에 따로 도착한다.

### F2. 수령인 장기 기억 (DB)
- **저장:** 대화에서 명시한 취향, 알레르기, 선물 이력, 만족도를 받는 사람별로 저장한다. 세션이 끝날 때 "다음에도 기억할까요?"를 한 번 묻고, 수락해야 저장한다.
- **반영:** 같은 사용자가 같은 수령인으로 다시 오면 기억을 조건에 자동으로 채운다. 화면 상단에 "지난 추석 기억을 반영했어요: 단 음식 X · 땅콩 제외 · 등산 [수정]" 한 줄을 보여준다.
- **수정:** [수정]을 누르거나 마이페이지에서 기억을 고치거나 삭제한다. 삭제는 실제 삭제다.
- **규칙:**
  - 알레르기는 사용자가 명시한 경우에만 저장하고, 저절로 사라지지 않는다.
  - 나이·관계로 취향을 추론하지 않는다.
  - 이번 대화의 말과 기억이 충돌하면 덮어쓰지 않고 묻는다.

### F3. 설명은 글이 아니라 태그와 칩
- **이유 태그:** 카드마다 2~3단어 태그 2~3개. 예: `차 좋아하심` `리뷰 많음` `8천원 여유`. 자세한 설명은 카드를 눌렀을 때만 펼친다.
- **대조 칩:** 1위와 2위가 실제로 다른 점 한 줄. 예: `2위보다 덜 달아요`
- **기억 반사실 줄:** 기억 때문에 1위가 바뀌었을 때만 보인다. 예: `'단 음식 X' 기억이 없었다면 1위는 약과 세트`
- **가격·만족 옵션 칩:** `아끼기 -1.5만원 · 같은 적합도`(누르면 그 예산으로 다시 추천) / `올리기 +9,000원 · 평점 4.4 → 4.7`(예산을 바꾸지 않고, 누르면 비교 트레이에 담는다).

### F4. 비싼 상품을 권하지 않는 가격·만족 균형
- **"올리기"는 근거가 있을 때만:** 현재 1위와 엔진 적합도(score)가 같고 평점이 더 높으며 늘어나는 금액이 설정 상한 이내인 상품만 대안으로 보여준다. 없으면 "같은 적합도에서 평점이 더 높은 상품이 없어요"라고 말한다. 예산과 카드 순위는 바뀌지 않는다.
- **상한 고정 수령인:** 교수님처럼 상한을 고정한 수령인에게는 "올리기"를 보여주지 않는다.
- **사용자 성향:** 가성비 / 균형 / 품질 우선 칩으로 시작한다. 고른 옵션에 따라 이번 세션의 성향을 조정한다. 같은 방향 선택이 반복되면 수령인 기억에 저장할지 묻는다.
- **이어지는 옵션:** 옵션을 하나 고르면 그 가격을 기준으로 옵션을 다시 계산한다.
- **숫자로만 표현:** "고급", "더 좋은 상품" 같은 근거 없는 표현은 쓰지 않는다.

### F5. 실험 조건 A/B (블라인드)
- **조건 A:** 이유 태그만
- **조건 B:** 이유 태그 + 대조 칩 + 기억 반사실 + 가격·만족 옵션
- 두 조건에서 처음 보이는 카드 상품과 순서는 같다. 진행자만 숨김 설정으로 조건을 바꾼다.

## Acceptance criteria
**기본 추천**
- **AC1.** 수령인·예산·배송비·수량이 정해진 요청은 공통 baseline `runTurn`과 같은 상품·순위·금액을 낸다. 기억이 없는 경우에 한한다.
- **AC2.** 필수 조건이 빠지면 상태를 바꾸지 않고 질문 하나만 반환한다.
- **AC3.** 카드 이벤트는 설명 이벤트보다 먼저 도착한다. LLM 설명이 실패해도 카드와 템플릿 태그는 보인다.

**기억**
- **AC4.** S1에서 세션 끝에 "기억할까요?"를 수락하면 어머니·아버지 기억이 각각 근거 문장과 함께 저장된다. 거절하면 아무것도 저장되지 않는다.
- **AC5.** S2에서 "부모님 설 선물 추천해줘"만 입력해도 땅콩 제외·단 음식 X·등산이 조건에 채워지고, 반영 한 줄이 보인다. 작년 선물은 카드에 "작년 추석에 드린 선물" 표시가 붙는다.
- **AC6.** S3에서 친구 추천에는 부모님 기억이 하나도 쓰이지 않는다. 다른 사용자(userB)의 기억도 쓰이지 않는다.
- **AC7.** 알레르기는 어떤 경로로도 줄어들지 않는다. 기억 수정, 반사실, 가격 옵션, LLM 해석 모두 포함한다. 땅콩 상품은 어떤 카드에도 나오지 않는다.
- **AC8.** S5에서 기억과 반대되는 말을 하면 기억을 바꾸지 않고 "기억을 바꿀까요?"를 묻는다.
- **AC9.** 기억을 삭제하면 다음 추천부터 반영되지 않는다. DB에서도 실제로 사라진다.

**설명**
- **AC10.** 조건 B의 기억 반사실 문장 속 상품은 그 기억을 빼고 다시 계산한 1위와 같다. 1위가 바뀌지 않으면 문장을 띄우지 않는다.
- **AC11.** 대조 칩·가격 옵션 칩의 숫자와 상품명은 전부 계산 결과와 일치한다. 검증 에이전트가 불일치를 잡아 템플릿으로 바꾼다.
- **AC12.** 조건 A에서는 대조·반사실·가격 옵션이 보이지 않는다. 카드 상품과 순서는 조건 B와 같다.

**가격·만족 옵션**
- **AC13.** "올리기"는 기준을 넘을 때만 보인다. 기준을 넘는 상품이 없으면 안내 문구가 나온다.
- **AC14.** S4(상한 고정)에서는 "올리기"가 보이지 않고, 상한을 넘는 상품은 어떤 설명에도 나오지 않는다.
- **AC15.** "아끼기" 칩을 누르면 그 예산으로 다시 추천하고 옵션을 다시 계산한다. "올리기" 칩은 비교 트레이에 담을 뿐 예산과 카드 순위를 바꾸지 않는다. 누르기 전에는 실제 세션 예산이 바뀌지 않는다.

**속도**
- **AC16.** 로컬에서 규칙으로 처리되는 요청은 카드까지 1초 이내다. LLM 해석이 필요한 요청은 3초 이내다.

## Success metrics (사용자 연구)
- 만족할 만한 상품을 찾기까지 걸린 시간: B가 A보다 길지 않음
- 최종 선택 확신·납득도(7점): B가 A보다 높음
- 2회차에 취향을 다시 말한 횟수: 1회차 대비 감소
- "받는 분을 고려했다고 느꼈다"(7점) 평균 5.5 이상
- 일부러 틀린 기억 1개를 심은 시행에서 사용자가 발견·수정한 비율: B가 A보다 높음
- 최종 가격이 처음 예산을 넘은 것에 대한 불만: 0명

## Out of scope
- **결제·주문:** 실제 결제·주문·배송, 구매 대행
- **엔진 변경:** 공통 엔진의 순위 규칙 변경과 작년 선물의 강제 순위 하락(결정 필요 사항 D1)
- **추천 범위:** 여러 명에게 서로 다른 상품 조합
- **인증·배포:** 정식 계정 인증과 공개 배포(실험은 참가자 ID 사용), 앱스토어 배포, 푸시 알림
- **다른 폴더 수정:** `b-pipeline/` 밖의 모든 파일 수정. 공통 코어·다른 설계 폴더·기존 앱 포함
