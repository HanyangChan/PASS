# B 기반 피드백 실험 모드

기존 `full-chat`의 행동 모델·도구·추천 계산·최종 응답 형식을 유지하고, 제안된 행동을 실행하기 전에 검토 모델이 검사한다. 검토 지적이 있으면 행동 모델로 돌아가 수정한다. 실제 서버 스키마·조건·금액 검사는 수정 후에도 그대로 집행된다. 프롬프트·역할이 다른 순차 LLM 호출이며 병렬 에이전트나 별도 서버는 아니다.

## 비교 모드

| 서버 CHAT_AGENT | 동작 |
| --- | --- |
| `full-chat` | B 기존 행동·관찰 루프 |
| `full-chat-feedback-1` | 제안된 행동마다 검토 최대 1회, 지적 시 수정 |
| `full-chat-feedback-2` | 제안된 행동마다 검토 최대 2회, 첫 검토가 지적한 경우에만 수정 행동을 재검토 |

최대 2회 모드도 첫 검토가 통과하면 1회로 끝낸다. 각 단계에 반복을 강제하지 않는다. 최종 허용 검토가 수정 요구인 경우 마지막 수정 행동은 추가 모델 검토 없이 서버 검사로 넘어간다. 따라서 ‘검토 횟수’가 모든 수정의 정확성을 보장하지 않는다.

각 턴의 실제 논리 LLM 호출은 **행동 + 검토 + 수정 합계 10회**, Agent 전체 제한은 **20초**, 도구는 기존 **5회**다. 기존 B의 기본 논리 호출 상한은 6회다. 예산 소진·공급자 오류·취소는 상태를 확정하지 않는다. 검토한 행동 수, 검토·수정 호출 수, 제한 도달 여부를 `routing.feedback`에 기록한다. 검토 텍스트나 내부 추론 원문은 진단에 넣지 않는다. `llmCalls`와 `usage`는 검토·수정까지 합산한다.

## 실행

저장소 루트에서 실행한다. 기존 개발 API가 실행 중이면 종료한 뒤 모드를 바꾼다. 기존 서버의 OpenAI 호환 LLM 설정을 사용한다. 키는 서버에서만 읽는다.

```sh
CHAT_AGENT=full-chat-feedback-1 npm run dev:api
CHAT_AGENT=full-chat-feedback-2 npm run dev:api
npm run test:feedback
npm run demo:feedback
npm run benchmark:feedback
```

`demo:feedback`은 모의 결정·검토로 복귀 경로를 확인하는 예제다. `benchmark:feedback`은 실제 모델을 호출하므로 사용량이 발생한다. 동일 모델·reasoning 끔·상품 스냅샷·과제를 사용해 B/검토 1회/검토 2회를 같은 실행에서 측정한다. 기존 20개 과제는 회귀 검사용 1회씩, 새 문구 10개 과제는 각 3회씩 실행하고 별도 보고한다. 기대 상태·채점 결과는 모델에 제공하지 않는다.

검토 조건은 조건의 귀속·근거·제약 유지·유효한 값·적절한 도구·응답 종료 계약이다. 짧은 동의 뒤 재질문, 음식 제외/포함 반전, 향 강도를 근거 없는 전체 카테고리 제외로 바꾸는 행동도 검토한다. 향 조건은 B와 같은 `avoid_fragrance` 상품명 규칙으로 처리하며, 적용 여부와 기존 조건 보존을 검토한다. 실제 향 강도를 측정했다고 표시하지 않는다. 기존 비교에서 발견한 오류가 설계에 반영되어 있으므로 기존 과제의 개선은 회귀 개선으로 해석한다. 새 문구 과제도 같은 과업 유형의 작은 내부 평가이며 외부 비공개 평가셋은 아니다.

로컬·운영 기본 `CHAT_AGENT`는 이 구현으로 변경하지 않는다. 기존 B를 같은 조건으로 재측정하며, 앞선 A/B 측정치와 다른 시점의 지연을 직접 합쳐 비교하지 않는다.
