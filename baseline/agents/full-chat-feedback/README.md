# B 기반 피드백 실험 모드

기존 `full-chat`의 도구·추천 계산을 사용한다. 서버가 명시적인 예산·배송비·납기·상품군과 대조해 확인한 단순 변경은 검토 호출을 생략한다. 수령인 변경, 알레르기 조건, 기존 제외 해제, 근거가 불분명한 변경에는 모델 검토를 적용한다. 상품 조회·비교·설명에는 공통 검증을 적용한다. 현재 요청에 알레르기나 수령인 변경이 들어오면 조회 제안도 해당 조건을 놓쳤는지 검토한다.

수령인·예산·배송비 포함 여부·상품군이 한 요청에서 명확히 확인되고 기존 수령인 변경이나 미해결 알레르기 조건이 없으면, 공통 코어에서 조건을 적용하고 추천까지 완료한다. API의 단순 상품 조회는 ASIN·모델 번호·상품명 토큰으로 고유하게 확인된 상품에 예산·재고·배송·제외 조건을 적용한다. 후보가 여러 개면 확인 질문을 표시한다.

API의 C(최대 2회 모드)는 채팅 추천 또는 특정 상품 조회의 최종 결과에 두 검증을 적용한다. 첫 검증은 사용자 요청과 적용된 조건을 대조한다. 다음 검증은 실제 후보의 가격·배송·재고·제외 성분과 상품 정보를 대조한다. 서버가 확인한 지적을 반영해 조건을 다시 확인하거나 해당 카드를 제외한다. 두 검증에도 기존 호출·시간 한도를 적용하며, 모델 검증이 일시적으로 실패하면 공통 코어로 검증된 결과와 실패 상태를 반환한다. 검증 횟수와 실제 사용량은 `routing.resultAudit`과 전체 호출 집계에 기록한다.

## 비교 모드

| 서버 CHAT_AGENT | 동작 |
| --- | --- |
| `full-chat` | B 기존 행동·관찰 루프 |
| `full-chat-feedback-1` | 검토 대상 행동마다 최대 1회, 지적 시 수정 |
| `full-chat-feedback-2` | 검토 대상 행동마다 최대 2회, 첫 검토가 지적한 경우에만 재검토 |

최대 2회 모드도 첫 검토에서 통과하면 1회로 끝낸다. 마지막 검토가 수정을 요구하고 수정 후에도 수령인 변경, 알레르기 조건 또는 기존 제외 해제 검토가 필요하면, 세션을 확정하기 전에 사용자에게 확인을 요청한다.

각 턴의 실제 논리 LLM 호출은 **행동 + 검토 + 수정 합계 10회**, Agent 전체 제한은 **20초**, 도구는 기존 **5회**다. 기존 B의 기본 논리 호출 상한은 6회다. 예산 소진·공급자 오류·취소는 상태를 확정하지 않는다. 검토 생략·호출·수정 횟수, 검토 사유 코드, 제한 도달 여부를 `routing.feedback`에 기록한다. `llmCalls`와 `usage`는 검토·수정까지 합산한다.

## 실행

저장소 루트에서 실행한다. 기존 개발 API가 실행 중이면 종료한 뒤 모드를 바꾼다. 기존 서버의 OpenAI 호환 LLM 설정을 사용한다. 키는 서버에서만 읽는다.

```sh
CHAT_AGENT=full-chat-feedback-1 npm run dev:api
CHAT_AGENT=full-chat-feedback-2 npm run dev:api
npm run test:feedback
npm run demo:feedback
npm run benchmark:feedback
```

`demo:feedback`은 모의 결정·검토로 복귀 경로를 확인하는 예제다. `benchmark:feedback`은 실제 모델을 호출하므로 사용량이 발생한다. 동일 모델·reasoning 끔·상품 스냅샷·과제를 사용해 B/검토 1회/검토 2회를 같은 실행에서 측정한다. 기존 20개 과제는 회귀 검사용 1회씩, 새 문구 10개 과제는 각 3회씩 실행하고 별도 보고한다. 기대 상태·채점 결과는 모델에 제공하지 않는다.

검토 조건은 조건의 귀속·근거·제약 유지·유효한 값·적절한 도구·응답 종료 계약이다. 짧은 동의 뒤 재질문, 음식 제외/포함 반전, 향 강도를 근거 없는 전체 카테고리 제외로 바꾸는 행동도 검토한다. 향 조건은 B와 같은 `avoid_fragrance` 상품명 규칙으로 처리하며, 적용 여부와 기존 조건 보존을 검토한다. 실제 향 강도를 측정했다고 표시하지 않는다. 기존 비교에서 발견한 오류가 설계에 반영되어 있으므로 기존 과제의 개선은 회귀 개선으로 해석한다. 새 문구 과제도 같은 과업 유형의 작은 내부 평가이며 외부 비공개 평가셋은 아니다.

로컬·운영 기본 `CHAT_AGENT`는 이 구현으로 변경하지 않는다. 기존 B를 같은 조건으로 재측정하며, 앞선 A/B 측정치와 다른 시점의 지연을 직접 합쳐 비교하지 않는다.
