## L1 근거 (2026-11-08)

- 이 문장은 유행을 전한 말이다. 누구의 취향이나 제약도 아니다. 이 설계의 추출기는 취향·제약 claim만 뽑으므로, claim이 0개인 것이 올바른 기대다.
- `expected_patch`(`{}`)와 `expect_question`(선택)은 그대로다. 행동에 대한 기대는 하나도 바뀌지 않았다.
- 2026-11-07 실행에서 t-03은 행동 실패가 없었다(2회 모두 미적용 + 질문). 그런데도 owner 채점에서만 오답으로 셌다.
- 이 변경으로 unknown→질문 비율은 오히려 내려간다(85.7% → 83.3%, t-03이 분모에서 빠짐). 유리한 숫자만 고른 변경이 아니다.
- 분석 근거: [results/2026-11-07T135005-analysis.md](results/2026-11-07T135005-analysis.md)

## 함께 바뀐 채점 방식 (평가셋 파일은 그대로, `evaluate.mjs`)

- S1: span 짝짓기를 "서로 포함" 또는 "가장 긴 공통 부분이 짧은 쪽의 60% 이상"으로 완화했다. 규칙(절 전체)과 LLM(짧은 구)의 span 표기 차이 때문이며, owner 값은 여전히 같아야 정답이다.
- S2: 예측 kind가 owner를 판단하지 않는 종류(`budget`·`quantity`·`delivery`·`recipient`·`other`)이고 기대 patch가 빈 문항이면 owner 채점에서 뺀다(`ownerNA`로 따로 셈). 기대 patch가 있는 문항은 계속 채점해서 실제 오류(예: m-02)를 가리지 않는다.
- S3: 분모가 0이면 `null`(화면 `n/a`)로 표시한다.
- S4: 시간 초과를 뺀 지표(`excludingTimeouts`)를 원본 지표와 함께 출력한다.

채점 방식이 바뀐 뒤의 숫자는 2026-11-07 결과와 직접 비교하지 않는다. 비교는 같은 결과 파일을 두 방식으로 계산한 분석 문서의 표로 한다.
