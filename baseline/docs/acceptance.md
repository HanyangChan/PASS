# 공통 수용 기준

`npm test`로 검사한다. 실제 LLM·DB·웹 화면 통합 검증은 포함하지 않는다.

1. 같은 카탈로그·조건이면 기존 PASS 엔진과 같은 순위·금액을 반환한다. 엔진 스냅샷 해시를 유지한다.
2. 필수 조건 누락은 한 턴에 질문 하나로 반환한다. 예산·배송비·수량을 임의 확정하지 않는다.
3. 충돌하거나 처리하지 못한 발화는 기존 조건을 변경하지 않는다. 해석기 확장 결과도 스키마 검증을 받는다.
4. 조건 일부 수정 시 나머지는 유지한다. 수령인 변경 시 이전 조건을 초기화한다.
5. 예산 비교는 실제 엔진을 다시 실행하며 입력·반환 세션과 버전을 변경하지 않는다.
6. 예산·배송비·제외 성분·재고를 지킨다. 결과가 없으면 조건을 자동 완화하지 않는다.
7. 버전이 오래된 요청은 거부한다. 잘못된 조건·상품·해석 결과는 실패한다.
8. 규칙으로 처리 가능한 발화는 LLM 확장 호출이 0회다. 외부 해석기는 호출자의 상태를 직접 수정할 수 없다.

실험 시 추가로 고정할 항목: 카탈로그 스냅샷과 해시, 대화 시나리오, 초기 세션, 엔진 버전, 모델·프롬프트 버전, 날짜, 난수 시드(해당 시). 측정할 항목: 제약 위반, 조건 해석 정확도, 질문 횟수, 추천 ID·순위, 설명 근거 일치, LLM 호출·토큰·지연·실패. 현재 테스트는 성능이나 사용자 연구 효과를 입증하지 않는다.
