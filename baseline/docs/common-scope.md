'모든 안에 표현된 책임'과 '완전히 같은 구현'은 구분해야 한다. 장기 기억, 설명 생성, 에이전트 자율성은 공통 책임이 있어도 구현 방식이 다르다. 따라서 베이스라인에는 합의 가능한 결정적 실행 경로를 두고 각 안의 구조를 강제하지 않는다. 보수적 파서와 질문 문구는 이 베이스라인을 실행하기 위한 초기 선택이며 문서의 다섯 안이 동일하게 정의한 규칙은 아니다.

## 분기 후 지킬 것

공통으로 고정할 것은 상품 입력 스키마, 추천 엔진·정렬 동률 규칙·비용 계산, 제약 검증, 가상 비교의 비변경성, 세션 버전 계약, 공통 테스트다. 새 후보 검색을 비교할 때는 같은 카탈로그를 사용하고 후보 풀 차이를 실험 변수로 기록한다. 출력 순위가 달라지는 실험을 설명만 다른 실험과 혼동하지 않는다.

각 안에서 바꿀 것은 해석기, 오케스트레이션, LLM·프롬프트, 검색 어댑터, 장기 기억 정책, 설명 표현, SSE와 병렬 실행이다. LangGraph나 생성 설명은 기존 `interpret` 포트만으로 모두 구현되지 않는다. 필요 시 브랜치별 어댑터·오케스트레이터를 추가하되 공통 엔진과 수용 기준은 재사용한다.

현재 GitHub 저장소 루트는 프로토타입 앱이고, `baseline/`에 공통 코어를 함께 둔다. 이전 구현과 과거 산출물은 정리했다. `a-router`는 서버 설정으로 기존 앱 채팅 API에 연결했다. 나머지 에이전트와 화면 선택 기능은 연결 전이다. 공통 코드 검토 후 앱과 베이스라인을 함께 포함한 공통 커밋에서 각 브랜치를 분기한다. 베이스라인은 저장소 바깥 소스에 의존하지 않아 단독 실행도 가능하다.
