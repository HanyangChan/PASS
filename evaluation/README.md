# 한국어 진단 평가 v1

## 목적과 한계

기존 개발 대화 10개와 별도 파일로 구성한 36개 합성 진단 사례다. 구현을 읽은 에이전트가 작성했으므로 **독립·블라인드 평가셋으로 간주하지 않는다**. 실제 사용자 표현 분포, 사용성, 추천 만족도는 측정하지 않는다. 기존 P0 독립 한국어 평가셋 과제의 초안이며, 완료 조건은 사람의 라벨 검토와 미공개 추가 대화 수집이다.

정답은 첫 실행 전에 작성했다. 실패를 없애기 위해 정답을 변경하지 않는다. 수정이 필요한 라벨은 이유와 변경자를 기록하고 데이터 버전을 올린다. 이 자료로 수정한 뒤의 점수는 회귀 개선 점수이며 일반화 성능이 아니다.

## 실행

프로젝트 루트에서:

```sh
node evaluation/run.mjs
node evaluation/run.mjs --name=after-fix
node evaluation/run.mjs --strict
```

`results/latest.json` 및 `.md`가 기본 출력이다. `--name`은 비교용 결과 이름이다. 첫 실행 결과 `results/baseline.*`는 보존하며 러너로 덮어쓸 수 없다. `--strict`는 실패 사례가 하나라도 있으면 종료 코드 1을 반환한다. 기본 모드는 진단 실패를 보고하고 정상 종료한다. 잘못된 검사 경로나 중복 ID는 실행 오류다.

## 지표 정의

- 사례 통과: 해당 대화의 **명시된 최종 검사 항목이 모두 일치**한 사례 수 / 36.
- 검사 항목 통과: 정답 파일에 명시된 최종 슬롯·질문 종류·차단 여부가 일치한 수 / 74. 배열은 순서 없이 비교한다.
- 질문은 구체적 문장 일치 대신 recipient, quantity, amount, scope, shipping, same, issue로 비교한다.
- blocked는 확인 질문이 남았거나 성분 정보 불충분으로 추천을 확정할 수 없는 상태다. 단순 후보 없음과 구분한다.
- 전체 슬롯 정확도, 매 턴 상태 정확도, 추천 품질, 반사실 설명 이해도를 이 점수로 주장하지 않는다.
- 각 결과에 코드 커밋, 데이터 SHA-256, 발화와 응답, 기대값과 실제값을 저장한다. 실행 전 코드 변경은 커밋해서 추적 가능한 상태에서 비교한다.

## 첫 결과와 수정 우선순위

현재 배포 소스 `ee50db9` 기준 **22/36 사례, 53/74 항목 통과**. 오류 14개를 공개한 상태로 기준선을 고정했다.

1. P0 의미 반전·잘못된 확정: 음수 예산(E08), 하한을 상한으로 해석(E09), 음수 수량(E14), 존재하지 않는 날짜(E26), 배송비 부정(E32), 범위 밖 상품(E36).
2. P1 수정·유지: 수량 정정(E16), 수신자 추가(E21), 취향 철회(E35).
3. P1 표현 범위·시작 안내: 한글 금액(E04), 쉼표 금액(E05), 원 생략(E10), 여섯 명(E17), 일반적인 시작 요청(E28).

## 사람 검토 및 독립 평가 완료 조건

- 팀원 2명이 발화와 기대 결과를 각각 검토하고 불일치를 합의한다. 모호한 요청은 허용 가능한 확인 질문을 함께 정의한다.
- 작성자가 아닌 참여자로부터 개인 식별정보 없는 대화를 추가 수집하고, 개발자가 보지 않는 평가용 묶음을 분리한다.
- 실제 고령 참여자의 표현을 별도 확인한다. 합성 페르소나 대화를 실제 참여자 데이터로 표시하지 않는다.
- 데이터셋 버전, 검토자, 합의일, 개발/평가 분리 기준을 기록한 뒤 독립 평가셋 과제를 완료 처리한다.
