# PASS 파일럿 평가 지표·결과 분석 계획

작성일: 2026-09-21. 적용 로그 버전: `pass-explanation-pilot-v2-single-gift`.
상태: 분석 계획·보고 양식 준비 완료. 실제 참여자 데이터 수집 및 효과 검증 전.

## 연구 질문과 비교

예산의 대조/반사실 설명(B)이 기본 추천 근거만 제공하는 화면(A)에 비해 추천 변화 이해를 돕는가? 추가 설명으로 난이도나 지출 압박이 높아지는지도 함께 살핀다. 이 평가는 고정 과제의 설명 UI를 평가하며 자연어 이해 정확도, 무이력 개인화의 효과, 음성 접근성을 측정하지 않는다.

현재 과제는 부모님 선물 하나(배송비 포함 30,000→42,000원)와 친구 선물 하나(60,000→72,000원)다. 두 과제 모두 첫 추천은 유지되고 후보 수가 증가한다. 결과는 이 유형에 한정하며 첫 추천이 바뀌는 경우로 일반화하지 않는다.

## 분석 단위와 데이터 정리

- 단위: 무작위 세션 ID 하나. 같은 사람이 여러 세션을 만들었는지는 로그만으로 확인할 수 없으므로 모집 시 중복 참여를 관리한다.
- 원본 JSON을 보존하고 분석 사본을 만든다. 버전·과제 정의가 다른 로그는 합산하지 않는다. ID가 같은 파일은 덮어쓰지 말고 이벤트·제출 수를 대조해 최종 파일을 확인한다.
- `trials`는 제출 완료 과제다. `current`는 마지막 제출 과제와 중복될 수 있으므로 별도 완료 행으로 추가하지 않는다.
- 첫 과제는 시작 이벤트, 다음 과제는 `trial_start` 이벤트로 시작 여부를 판단한다. 두 번째 과제 전 중단은 두 번째 과제의 실패가 아니라 미시작이다.
- 완료율 분모에는 확보된 모든 시작 세션을 포함한다. 중단·미완료를 제외하지 않는다. 새로고침·미전달 파일은 로그에 없으므로 진행자 모집 기록과 대조하고 '시작 N명 중 로그 확보 n명'을 별도로 보고한다.
- 중복, 버전 불일치, 손상 로그의 제외 사유·건수를 기록한다. 불리한 응답이나 긴 시간이라는 이유만으로 제외하지 않는다.

## 지표 정의

|지표|정의·로그 근거|보고 방식|
|---|---|---|
|세션 완료율|`status=complete` 세션 / 확보된 시작 세션|분자/분모와 %; 중단·실행 중 별도 건수|
|조건별 제출률|해당 조건 제출 과제 / 실제 시작된 해당 조건 과제|A/B 각각 분자/분모와 %|
|추천 변화 이해 정답률(주 지표)|`comprehensionCorrect=true` / 제출 과제|'모름'은 오답에 포함하되 별도 건수 표시; 무응답 미제출은 정답률 분모와 구분|
|선택 불가율|`selectedId=none` / 제출 과제|제품 선택과 구별; 제출 실패로 취급하지 않음|
|과제 소요 시간|`durationMs / 1000`|중앙값·최솟값·최댓값; 읽기·설문·비활성 탭 시간 포함|
|마지막 선택까지 시간|`selectionMs / 1000`|보조 지표; 순수 결정 시간으로 표현하지 않음|
|체감 난이도|`answers.effort`, 1 쉬움~5 어려움|각 점수 빈도·중앙값; 낮을수록 쉬움|
|선택 확신|`answers.confidence`, 1 낮음~5 높음|각 점수 빈도·중앙값|
|지출 압박|`answers.pressure`, 1 낮음~5 높음|각 점수 빈도·중앙값; 낮을수록 압박 적음|
|높은 예산 선택률|`budget=higher` / 제출 과제|A/B 각각 비율; 성공 지표로 간주하지 않음|
|예산 변경 횟수|과제별 `type=budget` 이벤트 수|중앙값·범위; 변경 없는 과제도 0으로 포함|

난이도·확신·지출 압박은 자체 단일 문항이다. 신뢰도·만족도 척도로 이름을 바꾸지 않는다. 미완료 응답과 시간은 완수 과제 평균에 채워 넣지 않는다.

## A/B 비교 절차

1. 로그 확보율, 그룹 0~3 배정 인원, 과제·조건·시행 순서별 시작/제출 수를 먼저 확인한다.
2. 모든 제출 과제의 A/B 기술통계를 제시하되 두 과제를 모두 제출한 완전쌍 수를 따로 밝힌다.
3. 완전쌍에서 세션별 B−A 차이를 계산한다. 시간·난이도·압박의 음수는 감소, 확신·이해 정답(0/1)의 양수는 증가다. 세션별 다른 과제에서 A/B를 경험하므로 과제 난이도가 섞인 비교임을 명시한다.
4. 부모님/친구 과제별 및 첫 번째/두 번째 시행별 결과를 나누어 과제·순서 효과를 확인한다. 작은 표본으로 인과 효과나 통계적 유의성을 주장하지 않는다.
5. 중단, 모름, 선택 불가 및 높은 난이도 사례를 진행자 관찰과 대조한다. 관찰 없이 로그만으로 원인을 단정하지 않는다.
6. 파일럿 이후 과제 변경이나 제외 기준 변경은 날짜와 이유를 남기고 새 버전으로 분리한다.

## 결과 보고 양식

아래 '미수집'은 0이 아니다. 실제 데이터 확보 후에만 채운다.

|항목|A|B|비교·주의점|
|---|---|---|---|
|시작/제출 과제 수|미수집|미수집|미시작과 중단 구분|
|이해 정답 수/제출 수|미수집|미수집|모름 건수 병기|
|선택 불가 수/제출 수|미수집|미수집|제품을 선택하지 못함|
|소요 시간 중앙값(범위), 초|미수집|미수집|완수 과제 기준|
|난이도·확신·압박 분포|미수집|미수집|1~5점별 빈도|
|높은 예산 선택 수/제출 수|미수집|미수집|추천 성공과 구별|
|완전쌍 B−A|미수집|미수집|완전쌍 수 및 과제/순서 효과 병기|

보고 문장: '시작 __명 중 __개 세션 로그를 확보했고 __개가 두 과제를 완료했다. A 정답률 __/__, B __/__였다. 이는 첫 추천이 유지되는 두 가상 식품 과제에서의 파일럿 관찰이며 일반적인 추천 품질 향상을 입증하지 않는다.'

## 다음 실행 작업

- 팀원이 과제 문구·이해 질문·분석 기준을 검토하고 모집 전 확정한다.
- 실제 브라우저에서 시작→두 과제→JSON 저장, 중단→JSON 저장 흐름을 검증한다.
- 수업 지침에 따른 참여 안내, 로그 전달 경로·보관 기간, 중복 참여 관리 방식을 정한다.
- 파일럿을 진행하고 위 표에 실제 결과를 입력한다. 현재 합성 진단 36/36이나 자동 테스트 통과 수를 사용자 실험 결과로 사용하지 않는다.
