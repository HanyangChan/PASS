# 수령인별 기억 및 구매 이력 MVP

AI 추천 화면의 **기억과 구매 이력 관리**에서 현재 대화의 선호·제외 조건을 사용자가 명시적으로 저장한다. 예산, 배송일, 목적은 장기 기억에 저장하지 않는다. 부모님/어머니/아버지는 별개의 대상이며 엄마/어머니, 아빠/아버지는 같은 이름으로 정규화한다. 현재 MVP의 자동 대상 인식은 어머니, 아버지, 부모님, 처가, 교수님, 직장 상사, 친구에 한정된다. 여러 대상 또는 불분명한 대상에서는 특정 인물의 기억을 자동 적용하지 않는다.

## 추천 흐름

1. 수령인이 바뀌면 이전 대상의 선호·제외 조건과 미해결 질문을 초기화하고, 서버에 이전 대상의 대화 문맥을 보내지 않는다.
2. 해당 수령인의 저장된 제외 조건과 선호를 채운다. 현재 요청에서 명시한 선호가 이전 선호보다 우선한다.
3. 선호가 비어 있으면 같은 수령인에게 구매 후 만족했다고 사용자가 등록한 상품의 카테고리를 기존 엔진의 선호 점수에 반영한다. 구매만 했거나 평가 전/불만족인 상품은 긍정 선호로 추론하지 않는다.
4. 게스트 규칙 경로와 로그인 서버 경로에 같은 조건을 전달한다. 서버가 저장된 알레르기 성분을 제거하면 제외 조건을 다시 적용해 서버에서 재계산한다.
5. 대화에 기억/구매 이력의 반영 근거를 표시한다. 성분 정보가 불완전하면 기존 엔진과 동일하게 상품 적합성 확정을 보류한다.

## 저장 범위 및 출처

AsyncStorage에 계정 ID별 또는 게스트 키로 분리하여 저장한다. 계정 전환 시 상위 Provider가 새로 마운트되어 다른 계정의 개인화 상태가 공유되지 않는다. 게스트 기록을 계정으로 자동 이동하지 않는다. 기기 간 동기화는 아직 지원하지 않는다. 읽기 실패 시 쓰기를 차단하며, 쓰기가 성공한 뒤에만 UI에 반영한다. 저장 실패는 오류로 표시하며 재시도할 수 있다.

최근 본 상품은 구매 이력으로 자동 전환하지 않는다. 관리 패널에서 실제 구매한 상품을 직접 등록해야 하며 `source=user_reported`로 구분한다. 기록 시간은 등록 시점이다. 주문/결제 검증과 구매일 추정은 하지 않는다. 등록 후 만족/불만족을 변경하거나 삭제할 수 있다. 최대 수령인 기억 100개, 구매 기록 100개를 보관한다.

저장된 기억은 관리 패널에서 삭제할 수 있다. 선호/제외 수정은 조건 편집 후 다시 저장한다. 알레르기 항목은 재저장만으로 제거되지 않는다. 해제하려면 기억을 명시적으로 삭제하고 현재 대화 조건도 수정하거나 새 대화를 시작한다. 기억 삭제/피드백 변경은 다음 새 대화에서 반영하며 진행 중 대화의 조건은 자동으로 지우지 않는다.

## 확인 시나리오

- “엄마는 땅콩 알레르기가 있어. 과일을 좋아해” 입력 → 조건 기억 → 새 대화 → “어머니 선물 5만원” → 땅콩 제외·과일 선호 유지, 상품 적합성 보류.
- 위 상태에서 “친구 선물” → 어머니의 조건 및 미해결 질문이 넘어가지 않음.
- 친구에게 산 과일 상품을 직접 등록하고 만족 선택 → 새 대화에서 친구 선물 요청 → 과일 선호 및 근거 표시.
- “친구 차로 추천” → 구매에서 추론한 과일 선호보다 이번 차 선호 우선.
- 저장된 기억 삭제, 구매 피드백 변경/삭제 후 새 대화 → 수정된 기록 적용.
- 다른 계정 로그인/로그아웃 → 계정별 기록 분리.

## 후속 단계

수령인 ID/별칭 관리, 사용자 JWT/RLS 기반 계정 동기화, 실제 주문 연동, 세부 구매일과 목적, 불만족 이유 반영, 정보 출처를 표시한 상품별 추천 설명, 기억 적용 전후 만족도 평가를 추가한다. 현재 단계는 실제 주문 데이터나 협업 필터링 모델을 사용하지 않는다.
