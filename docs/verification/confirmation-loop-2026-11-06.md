# 동의 응답 반복·향 조건 오해 점검

사용자 화면에서는 C가 추천 제안에 대한 `어/그래` 뒤에 확인 질문을 반복했고, 음식 제외가 음식 포함으로 뒤집힌 문장이 표시됐다. 실제 사용자 저장 기록은 읽거나 수정하지 않고, 화면과 유사한 합성 세션으로 실제 설정 모델을 호출했다. 원래 대화의 전체 상태를 확보한 정확한 재생은 아니다.

## 확인한 원인

- 카탈로그에 향 강도 속성이나 향 제외 필드가 없는데도 행동 모델과 검토 모델이 beauty/personal_care/decor 전체 제외로 바꾸려 했다. 합성 재현에서 실제로 관찰했다.
- 짧은 동의와 이전 어시스턴트의 잘못된 질문을 해석하는 지침이 약했다. 검토자가 이미 명시한 제외 조건을 재확인하게 하거나 지원되지 않는 향 조건을 추가하라고 지시했다.
- 검토자가 현재 턴 도구 관찰이 없는 결과 응답을 승인했다. 실행기는 안전하게 중단했지만, 사용자는 요청을 다시 말하라는 안내를 받았다.
- 검토자가 검색 행동을 ‘불필요한 질문’이나 ‘성급한 최종 응답’으로 분류해 이미 올바른 행동을 반복 수정시키기도 했다.

## 수정

- 행동/검토 프롬프트에 짧은 동의, 명시적 제외 우선, 빈 검색 결과의 정상 완료, 카탈로그 한계를 명시했다.
- 결과 행동에 화이트리스트 `limitations:["scent_strength"]`를 허용하고, 서버가 고정 안내문을 덧붙인다. 향 필터링을 적용했다고 표시하지 않는다.
- B 실행기와 C 검토기에 향 조건의 근거 없는 전체 카테고리 제외를 막는 기능 검사를 추가했다. 잘못된 후보는 실행하지 않고 제한된 호출 예산 내에서 수정 피드백을 돌려준다. C의 마지막 미검토 수정안도 이 검사를 거친다.
- C의 도구 없는 결과 승인과 행동 종류에 맞지 않는 검토 코드도 서버에서 보정한다. 실제 모델 호출 횟수와 한도는 유지한다.
- 공통 추천/가격 엔진, A, 모바일 UI는 이번 수정에서 변경하지 않았다. 로컬 API를 재시작해 반영했다.

## 검증과 한계

- 에이전트 테스트 89개, API 테스트 44개 통과. 코어 테스트와 B/C 실행 예제도 통과.
- `confirmation-loop-before-2026-11-06.json`: 수정 전 합성 카탈로그의 3가지 시나리오(직접 요청, 정상 제안에 동의, 음식 조건이 뒤집힌 제안에 동의), B/C 각 7턴. 반복 질문·근거 없는 제외·검토자의 잘못된 지시가 재현됐다.
- `confirmation-loop-after-2026-11-06.json`: 같은 시나리오 최종 수정 후 B/C 합계 14턴 모두 불필요한 질문 없이 종료, 음식 제외 유지, 근거 없는 카테고리 제외 없음, 각 시나리오 첫 응답에서 향 정보 한계 안내를 확인했다(`passed:true`).
- `confirmation-loop-catalog-2026-11-06.json`: 실제 상품 스냅샷 + 합성 초기 상태, 음식 제외와 향 제외 혼합 요청 → 어 → 그래, B/C 6턴 모두 정상 결과·음식 제외 유지·첫 응답의 향 정보 한계 안내를 확인했다. 검토 코드 최종 보정 직전 실행이며 해당 실행은 보정 없이도 모두 정상 완료됐다.

재현 명령: `node api/diagnostics/confirmation-loop.mjs <결과.json>`; 실제 상품 스냅샷은 세 번째 인자 `catalog`를 추가한다. 설정된 공급자 사용량이 발생한다. 사용자 인증/DB 기록/브라우저 조작을 포함한 검증은 아니다.

향 강도 필터 자체는 구현한 것이 아니다. 한계 코드는 해당 턴 안내이며 장기 향 조건 저장 기능이 없다. 알려진 향 관련 카테고리 오해는 서버 검사로 제한하지만 모든 자연어 의미 오류를 차단하는 일반 해석기는 아니다. 검토 모델의 판단과 호출 한도에 따른 실패 가능성은 남는다. 과거 A/B/C 시간·정확도 수치는 변경 전 버전 측정치이므로 수정 후 성능 수치로 재사용할 수 없다.
