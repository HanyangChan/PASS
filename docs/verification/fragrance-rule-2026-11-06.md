# 상품명 기반 향 제품 제외 규칙

사용자가 ‘향 강도 정보가 없어 적용하지 못했다’는 A 응답에 대해 규칙 추가를 요청했다. 향 강도 측정치를 만들어내지 않고, 상품명에 나타난 향 제품 종류를 제외하는 규칙을 구현했다.

## 동작

- 상태 `preferences`에 `avoid_fragrance`를 저장하고 UI에서 ‘향 제품 제외’로 표시한다.
- 한/영 상품명으로 향수, 방향제, 디퓨저, 향초, 인센스, 아로마/에센셜 오일 등을 식별한다. `name_en`도 검사한다. 명시적인 무향·unscented·fragrance-free 제품은 허용한다. 화장품/홈데코 전체 제외나 일반 헤어/카메라 diffuser 제외로 확대하지 않는다.
- A의 ‘향이 강한 제품은 빼고, 먹는 것도 제외해줘.’는 모델 호출 없이 향 태그와 먹는 상품군 제외를 함께 저장한다. 배송비 답변 전에도 조건을 적용하며, 이후 배송비 입력·예산 변경·화면 조회에서도 유지한다.
- ‘향 제품 제외 취소’로 향 규칙만 해제한다. 기존 음식 제외·알레르기 등은 유지한다.
- B/C에도 같은 허용 태그와 해석 지침을 제공했다. 공통 상품 필터가 일반 추천·예산 가상 비교·조회에서 적용한다. 서버는 상품명 기준이라는 안내를 표시한다.

## 공통 변경 범위

앱의 `lib/catalog.mjs`, `lib/engine.mjs`와 새 `lib/fragrance.mjs`를 공통 필터로 변경하고 baseline vendor 스냅샷 및 provenance 해시를 함께 갱신했다. 이는 A 전용 순위 로직이 아니라 모든 모드에 같은 후보 조건을 적용하기 위한 변경이다. 가격·예산 계산·순위 점수는 변경하지 않았다. 기존 저장 조건 구조를 유지해 DB 스키마 변경은 없다.

## 검증

- 코어 107개, baseline 90개, API 45개, 모바일 79개 테스트 통과. 모바일 lint/typecheck와 A/B/C 실행 예제 통과.
- 엔진 테스트: 한/영 상품명, 무향 예외, 무관한 상품군 유지, 필터 전 순위 계산, 예산 변경과 취소, 앱/스냅샷 결과 일치를 검사했다.
- 실제 설정 모델 + 3,376개 상품 스냅샷 + 합성 인증/세션으로 A/B/C 각각 ‘향·음식 제외 → 배송비 포함 → 7만원 변경’ 3턴, 합계 9턴을 검증했다. 모두 음식 제외와 향 태그를 유지하고, 광범위한 카테고리 제외 없이 필터된 추천 및 규칙 안내를 반환했다. A 첫 요청은 모델 0회다.
- 스냅샷에서 향 제품명 규칙에 해당하는 상품 93개를 확인했다. 결과는 `fragrance-rule-2026-11-06.json`에 기록했다. 재현은 `node api/diagnostics/fragrance-rule.mjs`이며 실제 공급자 사용량이 발생한다.

실제 향 강도·향료 성분 유무를 보장하지 않으며 상품명에 드러나지 않는 향은 놓칠 수 있다. 사용자 DB나 로그인된 브라우저 대화를 수정하지 않았다. 기존 시간/정확도 측정치는 변경 전 버전의 기록이다.
