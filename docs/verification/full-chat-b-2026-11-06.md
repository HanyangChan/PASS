# 전체 채팅 B안 검증 · 2026-11-06

구현: `baseline/agents/full-chat/`, `api/full-chat-agent.mjs`, 서버 `CHAT_AGENT=full-chat`. C안의 별도 재계획·검토·수정 모델은 포함하지 않는다.

## 실제 공급자 시험

`npm run smoke:full-chat`으로 기존 서버의 `deepseek-v4-flash`를 호출했다. 인증은 모형, 카탈로그·세션은 합성 데이터다. 실제 `/api/chat` 핸들러와 공통 추천 엔진을 실행했다. 이 결과는 실제 계정 로그인·브라우저·운영 DB·배포 검증을 의미하지 않는다.

| 시나리오 | 결과 | LLM / 도구 호출 | 지연 | 총 토큰 |
| --- | --- | --- | --- | --- |
| 인사 | 통과 | 1 / 0 | 732 ms | 1,002 |
| 조건 입력·차 선호·우유 제외 | 통과 | 2 / 1 | 2,543 ms | 2,509 |
| 추천 이유 | 통과 | 2 / 1 | 1,379 ms | 2,337 |
| 7만 원 가상 비교 | 통과, 실제 5만 원 유지 | 2 / 1 | 1,607 ms | 2,378 |
| 배송비 질문에 ‘아니요’ | 통과 | 2 / 1 | 1,440 ms | 2,346 |
| 충돌 예산 확인 | 통과, 실제 조건 유지 | 1 / 0 | 1,862 ms | 1,053 |

6개 모두 통과했고 HTTP 시도는 논리 LLM 호출과 같았다. 각 시나리오 1회 실행값으로 평균 성능·일관성·개선 효과를 입증하지 않는다. A안과 같은 과업을 반복한 통계 비교는 아직 수행하지 않았다.

초기 시험에서 모델이 빠른 답장의 예산 패치에 앱에서 허용하지 않는 `scope`를 복사하여 503이 발생했다. 모델 문맥에서 다중 선물 전용 필드를 제거하고 배송비 답장의 최소 패치 예시를 추가했다. 인자 검증을 완화하지 않았으며 이후 위 6개 시나리오가 통과했다.

## 자동 검사와 한계

B안의 모델 우선 진입, 도구 관찰, 상태 보존 가상 비교, 조건 수정, 수령인 초기 지정·변경, 성분 미확정 차단, 명시적 제외 취소, 호출 한도·진행 정체, 취소·시간 초과, 잘못된 모델 응답·공급자 실패를 모의 전송기로 검사한다. 기존 baseline 및 API 검사도 실행한다. `demo:full-chat`은 모의 결정으로 공통 엔진 실행을 확인했다.

최종 자동 검사: baseline 75개, API 37개 모두 통과했다. Worker 번들 dry-run도 통과했다. 로컬 B안 서버를 실행하고 실제 카탈로그를 읽는 `/health`에서 `agent=full-chat`, `llmMode=agent-loop`, `ok=true`, 상품 3,376개를 확인했다. 실제 사용자 인증으로 채팅하는 화면 검사는 수행하지 않았다. 로컬 `api/.dev.vars`만 B안으로 선택했으며 운영 설정·배포는 변경하지 않았다.

최종 문장은 검증된 엔진 결과나 대화 템플릿으로 렌더링한다. 모델의 다음 행동 선택 효과를 비교할 수 있지만 자유 생성 문장의 품질을 비교하는 구현은 아니다. 초기 B안은 최종 선택한 도구 결과를 표시하며 여러 결과를 자유롭게 종합하는 보고서 생성 기능은 포함하지 않는다.
