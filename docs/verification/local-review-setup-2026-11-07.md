# 새 환경의 PR #15 실행 확인

로컬에만 있던 Supabase/모델 설정 때문에 검토자에게 실행 방법이 재현되지 않는 문제를 보완했다.

## 변경

- `npm run setup:local`이 공개 설정 예제로 모바일/서버 환경 파일을 생성한다. 모바일 API는 기본 로컬 주소로 지정하고 기존 파일은 덮어쓰지 않는다.
- 모바일과 서버의 기본 에이전트를 A로 맞췄다. B/C는 서버 모델 키를 설정한 후 명시적으로 선택한다. 키 없는 규칙 경로와 로그인 없는 로컬 기기 경로는 기존 구분을 유지한다.
- 서버의 빈/placeholder Supabase 값이 정상 모바일 공개 설정을 덮어쓰지 않는다. 실제 서버 값과 프로세스 환경 변수의 우선순위는 유지한다.
- Node/Supabase/모드 설정 오류를 시작 시 알려주고, 포트 충돌을 구체적으로 안내한다. `API_PORT`로 개발 포트를 변경할 수 있다.
- 로컬 Node 기본 CORS는 localhost/127.0.0.1의 8766, 8081, 19006만 허용한다. 명시적 allowlist와 운영 Worker의 정책은 그대로다.
- health는 상품 조회 실패 시 503을 반환하고 `availableAgents`로 서버가 구성한 A/B/C 범위를 표시한다. 모델 키 유효성이나 모델 응답을 검증하는 시험은 아니다.
- README에 최초 설치/설정/로그인/모델 키/기존 환경 파일/API 주소/포트 확인 절차를 추가했다.

## 검증

PR 인덱스만 내보낸 별도 소스 사본에서 수행했다. 미커밋 상품 상세 화면 변경과 실제 로컬 환경 파일/모델 키는 포함하지 않았다. 설치된 node_modules는 연결해 사용했으므로 의존성 새 다운로드 검증은 아니다.

1. 설정 없이 시작: exit 1, `npm run setup:local` 안내 확인.
2. `npm run setup:local`: 공개 예제 두 파일 생성 확인. 모델 키 없음.
3. `API_PORT=18789 npm run dev:api`: A 규칙 모드로 시작.
4. 실제 `GET /health`: HTTP 200, `ok:true`, 상품 3376개, `availableAgents:["a-router"]`.
5. `Origin:http://localhost:8081`의 OPTIONS: HTTP 204.
6. 같은 포트로 중복 시작: exit 1, 기존 API 종료/API_PORT 변경 안내 확인.
7. `npm test`, 모바일 lint/typecheck/build:web 전부 통과.
8. 새 테스트는 파일 생성의 멱등성·기존 비밀값 보존·placeholder fallback·프로세스 우선순위·구성 오류·health 실패 상태/모드 목록을 검사한다.

실제 다른 사용자의 로그인 세션이나 로그인 후 채팅을 대신 실행하지 않았다. 서버 채팅에는 Supabase 인증이 필요하며, B/C에는 해당 공급자에서 쓸 수 있는 모델 키가 필요하다. 공개 Supabase 예제의 실제 조회는 검증 시점에 확인한 결과이며 프로젝트의 접근 정책/가용성은 별도다.
