# A 현재 설정 vs B 풀 에이전트 실제 비교 · 2026-11-06

현재 구현에서는 A가 업무 성공률과 정형 요청 응답 속도에서 앞섰다. B는 이번 자연어 업무 3종에서 더 빠르고 모두 성공했지만, 취향의 주체를 잘못 적용하는 오류와 응답 종료 계약 때문에 조건 수정이 취소되는 문제가 드러났다. 에이전트 코드를 고치지 않고 실패를 포함해 측정한 결과다.

## 측정 조건

- 실행: 2026-11-06 08:03:15 ~ 08:06:07 KST.
- 같은 20개 과제 × 3회 × A/B. 에이전트당 60개 과제 실행, 66개 API 요청. 연속 대화 과제는 3턴이다.
- A: `a-router`, 현재 `single` 모드. B: `full-chat` 기본 행동·관찰 루프. 모델은 둘 다 `deepseek-v4-flash`, temperature 0.
- 같은 초기 조건·사용자 문장·상품 3,376개·공통 추천 엔진. 실제 공급자 호출과 API 핸들러를 실행했다. 인증·세션은 합성 데이터이며 카탈로그는 고정된 로컬 스냅샷이다.
- A/B 실행 순서를 번갈아 배치하고 반복별 과제 순서를 순환했다. 별도 워밍업이나 캐시 제거는 하지 않았다.
- 정확도는 미리 정한 조건 반영·보존, 확인 질문, 추천 결과·계산·설명을 모두 만족하는 과제 성공률이다. 추천 결과 정답은 기대 조건을 같은 공통 엔진에 넣어 계산했다. 상품 선택 자체의 품질이나 사용자 만족도 점수는 아니다.

## 실패 사례

- **A:** 인사 3/3회에 인사 대신 수령인 질문을 반환했다. 감사 3/3회에 감사 응대 대신 추천 안내를 반복했다. 차 선호·우유 회피·기존 견과류 제외 유지 과제는 1/3회에 503으로 실패했다.
- **B:** “나는 커피를 좋아해”를 3/3회 모두 어머니의 커피 선호로 적용했다. 주는 사람과 받는 사람의 조건 귀속을 확인하지 못한 실제 조건 오류다.
- **B:** 견과류 제외 2/3회와 명시적 예산 수정 1/3회에서, 조건 수정 도구 뒤 모델이 `respond: acknowledge`로 종료했다. 현재 런타임은 도구 실행 후 일반 확인 응답을 `unfinished_tools`로 막고 변경을 취소하므로 요청한 조건이 반영되지 않았다. 모델 해석만의 오류가 아니라 모델 출력과 런타임 종료 계약의 불일치도 포함한다.
- **B:** 존재하지 않는 날짜는 1/3회에 확인 질문 대신 잘못된 수정 시도로 503이 발생했다. 서버 검증은 잘못된 날짜 적용을 막았다.
- **B:** 감사 2/3회는 “네, 이어서 궁금한 점이나 바꾸고 싶은 선물 조건을 알려주세요”라는 일반 확인 응답이었다. 지정한 감사 응대 문구 규칙에는 미달했지만 사실 오류나 조건 오류는 아니다. 일상 대화 점수는 문구 기준의 영향이 있으므로 업무 성공률과 분리해 해석해야 한다.

## 해석과 한계

지금 상태로 기본 처리 구조를 고르면 A가 더 안정적이다. B는 이번 자연어 문구의 처리와 인사 응대에서 장점이 있었지만, 전체 대화를 모델에 맡기는 것만으로 업무 정확도가 좋아지지는 않았다. B를 발전시키려면 먼저 취향의 주체 검증과 도구 실행 후 종료 계약을 보완하고, 같은 과제로 다시 비교하는 것이 적절하다. 이번 측정 중 해당 코드는 수정하지 않았다.

- 현재 설정 그대로 비교했다. 실제 전송값은 A의 `reasoning` 옵션 생략, B는 `reasoning.enabled=false`였다. 따라서 자연어 구간에서 B가 더 빠른 결과를 구조만의 효과로 단정할 수 없다. 이를 분리하려면 reasoning 옵션까지 맞춘 별도 실험이 필요하다.
- 브라우저 렌더링·실제 Supabase 인증·DB 조회 네트워크 시간은 제외했다. A의 약 20~40ms는 이 측정 범위에서의 서버 처리 시간이며 사용자의 실제 화면 응답 시간을 뜻하지 않는다.
- 과제별 반복은 3회뿐이고 문구도 고정되어 있다. 일반적인 정확도, 통계적 유의성, 다른 입력 분포에서의 평균 성능을 확정하지 않는다. 토큰은 공급자 보고 합계이며 실제 비용은 가격·캐시 정책에 따라 다르다.
- 최종 응답은 양쪽 모두 주로 엔진 기반 템플릿이다. 자유 생성 설명의 문장 품질을 비교한 결과는 아니다.
