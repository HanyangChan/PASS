사용자 요청에 따라 사람 평가 대신 **현재 코딩 어시스턴트가 LLM 평가자 역할**을 맡았다. 별도 모델·독립 평가자·실제 사용자를 이용한 연구는 아니다. 유료 모델 호출, 운영 계정 생성, 운영 Supabase 쓰기, push·PR·merge·배포는 수행하지 않았다.

## 1. 평가와 실제로 발견한 문제

### 새 문장

기존 135개 대화에 없는 문장 20개를 결과를 보기 전에 고정하고 파일 SHA-256을 기록했다. 12개는 먼저 진단에 사용하고, 나머지 8개는 첫 수정 후 처음 실행했다. 게스트와 실제 Worker 핸들러의 규칙 모드 A를 가짜 인증으로 각각 검사했다. 조건 해석 검사는 소형 합성 카탈로그로 실행해 실제 상품 재고 부족과 분리했다.

| 묶음 | 최초 엄격 검사 | 수정 후 엄격 검사 | 해석 |
|---|---|---|---|
| 진단 12문장 × 2경로 | 2/24 | 22/24 | 배송비 동의어·연결어·이전 대상/예산 문맥 처리 누락을 수정 |
| 처음 보류했던 8문장 × 2경로 | 4/16 | 10/16 | 첫 수정만으로 일반화되지 않는 표현이 남아 추가 수정. 이후에는 회귀 자료로 취급 |
| 모든 수정 후 별도로 만든 6문장 × 2경로 | 첫 실행 12/12 | 같은 첫 실행 결과 | 평가 전에 문장·기대값과 해시를 고정. 이 문장에 맞춘 후속 수정은 하지 않음 |

이 문장들은 같은 구현자가 만든 내부 새 표현이다. 독립 외부 작성자의 비공개 벤치마크로 표현하지 않는다. 처음 보류한 문장도 결과를 보고 수정한 뒤에는 더 이상 독립 평가셋이 아니다.

남은 엄격 검사 불일치는 원문 기대값을 고쳐 없애지 않았다.

- N12: 존재하지 않는 11월 31일을 확인하고 요청 전체를 적용하지 않아 예산도 null로 남는다. 고정 기대값은 유효 예산 부분 적용을 요구했다. 기존 원자적 검증 정책을 유지했고 안전한 확인으로 판정했다.
- H02: 기대값 `상사`와 기존 정규형 `직장 상사`의 문자열 차이다. 역할 의미는 같지만 엄격 실패는 그대로 기록했다.
- H04: 꽃다발 변경 시 `category:flower` 외에 새 `type:bouquet`가 추가된다. 고정 평가 기대값은 그대로 두었으며, 의미상 더 정확한 해석으로 판정했다.
- H07: 수령인이 어머니에서 친구로 바뀌면 이전 예산을 자동 상속하지 않고 새 예산을 묻는다. 고정 기대값은 추가 질문이 없기를 요구했다. 현재 대상을 분리하는 확인 정책을 유지했다.

LLM의 별도 의미 검토에서는 20개 중 17개를 조건 해석 완료, 3개(N12/H03/H07)를 적절한 확인 질문으로 판정했다. **이를 일반 정확도 100%로 환산하지 않는다.** H03은 필기구 선호를 반영하되 모호한 음료 제외 범위를 확인한다. 원문·기대값·실제 상태·엄격 실패 기록은 모두 보존했다.

### 실제 상품 적합성

수령인·상황·원문 요구를 고정한 6과제를 아마존/네이버/통합 카탈로그에서 실행했다. 가격·배송비·제외 조건·실제 상품명을 읽어 0=명백한 불일치, 1=부분 적합/정보 부족, 2=요구 적합으로 개별 상품을 평가했다. 엔진 점수를 평가 정답으로 사용하지 않았다.

발견한 대표 오류:

- 아마존에 꽃다발 후보가 없는데 견과류·액자·프로틴을 제시했다.
- 아마존의 고등학생 필기구 요청에 팝콘·인형·캐슈넛을 제시했다.
- 네이버 시계 후보가 1개뿐인데 나머지 자리를 차·한우로 채웠다.
- `티백 원두 커피`라는 드립백 제목의 티백 단어 때문에 차로 분류했다.
- 고등학생 조카를 초등학생과 구분하지 못해 어린이날 단체용 지우개 60개가 추천됐다.
- 일반적인 할머니 건강 선물에 운동용 프로틴/BCAA가 앞섰다.
- 술을 못 드시는 직장 상사에게 여성용 양말 묶음·와인잔이 앞섰다.

## 2. 수정 사항

1. **문장 해석:** 배송료/택배비/운송료, 배송 포함, 상한 금액의 자연스러운 표현, 명시적인 이전/현재 대상 대비, 현재 예산과 일치하는 과거 금액의 정정, `이라면` 가상 비교, 알려진 연결어를 처리한다. 해석하지 못한 조건은 여전히 질문한다.
2. **현재 의도 보존:** 차보다 시계, 꽃다발로 변경 등 명시적 교체에서는 이전 상품군과 그 세부 타입을 함께 정리한다. 수령인 변경은 이전 대상 조건을 자동 상속하지 않는다.
3. **상품군·종류 일치:** 앱용 `strictGiftPreferences` 옵션에서 요청한 상품군과 종류만 후보로 남긴다. 세 개를 맞추려고 무관한 종류를 섞지 않는다. 옵션 없는 공통 엔진 기본 동작은 유지한다.
4. **세부 종류:** `type:writing`과 `type:bouquet`를 도입했다. 필기구는 볼펜·샤프 등으로, 꽃다발은 해당 형태로 좁힌다. 커피가 명시된 드립백은 티백이라는 단어만으로 차가 되지 않는다.
5. **제외 범위:** 와인 제외는 `avoid_wine`으로 처리해 주류 전체 제외로 확대하지 않는다. 불분명한 음료 제외는 지원 가능한 범위를 묻는다.
6. **연령·상황:** 고등학생/중학생·성인이라는 명시 정보를 보존한다. 선물 적합도는 운동 목적 없는 고령 수령인의 운동 보충제, 직장 관계의 성별 특정 양말 묶음, 주류를 피하는 상황의 와인잔 등을 낮춘다. 상품명 기반 맥락 점수이며 의료·취향 사실을 추정한 것은 아니다.
7. **응답 일치:** 채팅 메시지와 추천 카드가 같은 랭킹 옵션을 사용하게 했다. 카드가 없는데 채팅은 '골랐어요'라고 말하는 경우를 막았다. 세부 태그는 화면에 내부 문자열 대신 꽃다발·필기구 선호로 표시한다.
8. **빈 결과 복구 UI:** 이미 5만원인 예산을 그대로 재전송하던 버튼과 피할 성분까지 한 번에 지우던 버튼을 제거했다. 예산/상품 종류를 직접 입력하게 하며 제외 조건을 자동 해제하지 않는다. 입력 중인 초안도 지우지 않는다.

공통 lib 변경은 vendor에 LF로 복사하고 provenance 해시를 갱신했다. 기존 테스트 중 꽃다발·볼펜 두 사례의 세부 타입 기대값만 의도한 기능 확장에 맞춰 갱신했다. 새 문장 평가의 고정 기대값은 바꾸지 않았으며 '향수 말고 커피' 합의도 유지했다.
