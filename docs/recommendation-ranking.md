# 공통 추천 순위 v2

`gift-budget-diversity-v2`, 2026-11-05. 앱의 `lib/`와 베이스라인의 `baseline/src/vendor/`에 같은 정책을 적용한다. 이는 A 설계만을 위한 엔진 수정이 아닌 공통 추천 정책 변경이다. 스냅샷 해시는 `baseline/src/vendor/provenance.json`에 기록하며 이전 정책은 Git 이력에 보존한다. 다른 담당자의 에이전트 폴더는 수정하지 않는다.

현재 범위는 가공된 3,376개 상품이다. `scripts/catalog/README.md`의 전처리 과정에서 원본 데이터의 일부 상품군과 리뷰·평점 조건으로 추렸다. 원본 수십만 개를 실시간 조회하지 않는다. 가격·배송·재고 일부는 데모용 가공값이다.

## 순위 계산

1. 제외 상품군·성분, 브랜드, 포장, 도착일, 재고, 예산 상한을 먼저 지킨다. 배송비 포함 여부와 총예산의 세트 수는 적격 판정과 예산대 적합도 양쪽에 똑같이 반영한다.
2. 기존 수령인 상품군(+1), 명시 상품군(+3), 단맛 선호(+0~2)를 유지한다. 명시된 차/커피 종류와 상품명 분류가 일치하면 +3을 추가한다. 종류 분류는 한·영 상품명 규칙이며 확정 상품 메타데이터나 LLM 판단이 아니다.
3. 선호 점수가 같을 때 예산대 적합도 70%, 리뷰 신뢰도 30%로 정렬한다. 예산대 적합도는 비용/상한 비율이 0.8일 때 최고이며 `max(0, 1 - abs(비율 - 0.8)/0.8)`이다. 리뷰는 `min(1, log(1+리뷰수)/log(10001))`로 완만하게 반영한다. 동점은 기존 상품군 상대 리뷰·리뷰 수, 낮은 가격, ID 순서로 결정한다. 80%는 부드러운 선호이며 가격 하한이 아니다. 비싼 상품이 더 좋은 상품이라는 의미도 아니다.
4. 상위 3개를 고를 때 동일 선호 점수 후보 중 유사 상품명(용량·숫자를 정규화) -0.5, 동일 브랜드 -0.15, 동일 상품군 -0.06 감점을 적용한다. 기본 효용 차이가 0.3을 넘는 후보는 다양성만을 위해 올리지 않는다. 유사 후보밖에 없으면 중복도 허용한다.
5. 최고 선호 점수 후보가 전부 예산의 절반 미만이면 낮은 가격대에 몰려 있다는 안내를 표시한다. 높은 가격의 다른 종류로 강제 대체하지 않는다.

같은 데이터·조건이면 결과는 동일하다. 랜덤 교체나 사용자가 보지 않은 상품을 찾는 기록 기반 탐색은 구현하지 않았다. 예산·선호 변경에 대한 반응과 한 번에 제시하는 3개 사이의 다양성을 개선했다. 예산을 올리는 가상 비교도 이 정책으로 다시 계산하며 실제 조건은 바꾸지 않는다.

차를 좋아한다면 `category:coffee_tea`와 `type:tea`, 커피라면 `category:coffee_tea`와 `type:coffee`를 추출한다. 기존에 저장된 넓은 상품군 태그만으로 차/커피를 소급 추측하지 않는다. 종류 태그만 입력해도 종류 일치 점수는 적용된다.

## 확인

```sh
npm test
npm --prefix mobile run lint
npm --prefix mobile run typecheck
npm --prefix baseline run demo:agent -- a-router
```

`tests/ranking.test.mjs`는 예산 변화, 배송비·수량, 상한 유지, 유사 상품·브랜드 분산, 차/커피 구분, 저가 후보 유지, 실제 3,376개 카탈로그를 검증한다. API `/health`의 `rankingPolicy`에서 실행 버전을 확인할 수 있다. UI에서는 새 대화에 “엄마 차 좋아해 예산 10만원 배송비 포함”을 입력한 뒤 예산을 3만원으로 바꿔 비교한다. 데이터 내 차 후보가 낮은 가격대라면 10만원 예산이어도 8만원짜리를 만들어내지 않는다.
