# PASS 2안: Rule-based Hybrid

문서화 범위: **구현 예정인 비교 설계**. 현재 API에 이 비교 모드가 구현·배포되었다는 뜻은 아니다.

[메인 README의 구조도](../../README.md#2안-rule-based-hybrid) · [Mermaid 원본](architecture.mmd) · [1안 LLM Agent](../llm-agent/README.md)

## 목적과 제어 주체

백엔드가 전체 실행 흐름을 결정하고, 규칙으로 처리하기 어려운 자연어 해석이나 복잡한 설명에만 LLM을 제한적으로 사용하는 방식이다. LLM이 다음 도구를 선택하거나 도구 관찰 결과로 자율 재계획하는 루프는 없다.

‘추천 요청인가’만으로 LLM 호출 여부를 결정하지 않는다. 명확한 조건의 추천은 LLM 없이 처리할 수 있고, 추천 외 요청도 복잡한 해석이 필요하면 LLM을 사용할 수 있다.

## 요청 처리

1. 서버가 인증·입력·상태 버전을 검증한다.
2. Rule-based Router가 조건 변경·추천·설명·가상 예산 비교 등의 요청을 분류한다.
3. 규칙 파서가 현재 요청에서 조건 후보를 추출한다. 해석하기 어려운 요청만 서버가 정한 단일 LLM 추출 단계로 보낸다.
4. 서버가 후보를 검증한다. 정보가 부족하면 질문하고 이번 요청을 종료한다. 명확한 수정은 검증 후 반영하며 변경하지 않은 조건은 유지한다.
5. Router가 필요한 공통 엔진 함수를 직접 호출한다. 상품·순위·금액은 엔진이 결정한다.
6. 결과를 검증하고 템플릿으로 추천·이유·예산 비교를 표시한다. 복잡한 설명은 서버가 정한 별도 단일 LLM 생성 단계로 처리할 수 있으며, 반환 문장의 상품·금액·근거를 다시 검증한다.

LLM 단일 호출은 각 허용 단계에서 한 번 호출한다는 뜻이다. 추출과 설명을 모두 사용하는 요청의 총 호출 수는 별도로 기록·제한한다. 모델이 스스로 추가 호출을 결정할 수 없다. 오류 시 서버가 정한 복구 안내나 질문으로 종료하며, 호출·비용·시간 제한은 서버가 관리한다.

## 공통 엔진과 상태

| 기능 | 공유 구현 |
| --- | --- |
| 추천·정렬 | `recommend`, `rankProducts` |
| 금액 계산 | `budgetCost` |
| 가상 예산 비교 | `budgetAlternatives` |
| 조건 검증·유지·변경 | 공통 상태 및 검증 계층 |
| 상품 데이터 | 같은 카탈로그 스냅샷 |

함수는 [추천 엔진](../../lib/engine.mjs), [예산 비교](../../lib/counterfactual.mjs)에 있다. Router·LLM 추출/설명 제한·비교 모드 전환은 구현할 항목이다.

세션 메모리는 구조화 조건·미해결 질문·추천 결과를 보존한다. LLM 응답이 메모리를 직접 덮어쓰지 않으며, 후보 검증은 서버가 수행한다. 장기 선호는 사용자가 저장한 범위만 활용한다.

## 사용자 확인과 실패 복구

- 가상 비교는 상태 복제본에서 실행하고 ‘후보 증가’와 ‘상위 추천 변경’을 구분한다.
- 예산 증액·제외 조건 완화 제안은 사용자가 적용할 때 상태 버전을 확인한 뒤 반영한다.
- 모호한 조건은 추정하지 않고 질문한다. 이미 명확히 요청한 일반 수정은 검증 후 반영하고 되돌리기를 제공한다.
- 데이터·도구·LLM 오류를 조건 완화나 다른 해석으로 숨기지 않는다. 기존 상태를 보존하고 복구 방법을 안내한다.
- 상품 정보와 정책 문서 속 명령은 데이터로만 취급한다. 내부 추론 대신 실행 상태와 근거를 표시한다.
- LLM이 생성한 설명도 도구 근거와 대조한다. 현재 카탈로그의 배송·재고 등 데모 속성을 실제 거래 정보로 확정하지 않는다.

## 1안과 비교

두 안의 차이는 추천 알고리즘보다 실행 제어 방식이다. 1안은 LLM이 다음 행동·도구·종료를 선택하고, 2안은 서버가 선택한다. Hybrid도 동일한 대조·반사실 설명 기능을 제공한다.

비교 실험은 동일 초기 조건의 독립된 세션과 같은 상품·엔진을 사용한다. LLM·도구 호출 수, 비용, 응답 시간, 조건 정확도, 과업 완료율, 설명 이해도와 신뢰도를 측정한다. 호출 수·비용 감소나 정확도 개선은 아직 검증하지 않은 가설이다.

실행 구조 2종 × 대조·반사실 설명 유무의 4조건 비교 계획은 [1안의 비교 설계](../llm-agent/README.md#비교-설계-2안-rule-based-hybrid)를 따른다.
