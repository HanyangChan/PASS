# 한국어 명절 선물 추천 MVP — 시작 자료

## 목표와 범위
한국어 명절 선물 대화에서 조건을 정확하게 갱신하고, 변경 내역 표시가 사용자의 오류 발견과 수정에 도움이 되는지 평가한다. 구매 이력이나 로그인 없이 한 세션만 사용한다. 첫 대상은 식품 선물세트다.

이 폴더는 연구 자료이며 저장소 루트에 실행 가능한 규칙 기반 데모가 있다. 상품 30개, 브랜드, 가격, 배송일, 성분 정보는 모두 합성이다. 실제 상품·가격·배송 보장 또는 실제 명절 일정으로 사용하면 안 된다. 관련 연구의 신규성 주장은 여기서 검증하지 않았다.

## 파일
- products.json: 6개 상품군 × 5개 상품, 총 30개.
- state-template.json: 세션 초기 상태.
- test-dialogues.json: 10개 대화, 30턴의 변경 사항·전체 정답 상태·확인 질문 주제.
- test-dialogues.md: 사람이 읽기 편한 테스트 대화.
- data-contract.md: 데이터 의미와 상태 갱신·검색 규칙.

## 구현 순서
1. JSON 카탈로그를 읽고 예산·브랜드·제외 조건·포장·배송일 필터 함수를 만든다.
2. LLM 없이 test-dialogues.json의 expected_patch를 순서대로 적용한다. 매 턴 expected_state와 일치하는지 확인한다.
3. 사용자 발화와 이전 상태를 입력받아 변경 사항을 추출하는 LLM 연결을 추가한다. LLM 출력은 타입과 허용 필드를 검증한 뒤 적용한다.
4. 변경 전후 상태를 코드로 비교해 현재 조건 패널과 변경 내역을 만든다. 전체 상태를 LLM이 매번 재작성하도록 맡기지 않는다.
5. 필터를 통과한 후보를 선호 속성으로 정렬해 최대 3개 표시한다. 상품 ID와 구조화된 속성으로 추천 근거를 생성한다.
6. 가상 예산을 재계산해 비교 카드를 표시하고, 동일 조건 패널에서 비교 설명의 효과를 평가한다.

벡터 검색과 실제 상품 수집은 기본 동작을 확인한 후 추가한다. 가격 등 필수 조건을 벡터 유사도로 대체하지 않는다.

## 첫 완료 기준
- 30턴에서 변경 후 상태가 정답과 일치한다.
- 새 발화에 없는 이전 조건이 유지되고, 명시적 해제가 반영된다.
- 총예산은 수량을 곱해 검사하고 배송비 포함 여부를 반영한다.
- 후보가 없으면 조건을 임의로 완화하지 않고 사용자에게 조정할 조건을 묻는다.
- 모호한 예산이나 상대 날짜를 임의의 확정 값으로 저장하지 않는다.
- 추천 근거는 상품 데이터에 존재하는 속성만 사용한다.
- 알레르기 정보가 불완전한 상품을 안전하다고 추천하지 않는다.

## 현재 연구 방향과 평가 계획

현재 두 축은 **무이력 세션 개인화 + 대조·반사실 추천 설명**이다. 턴별 변경 표시는 지원 기능으로 유지한다. 자세한 정의, 구현 범위, 평가 설계는 [비교 설명 설계](counterfactual-explanations.md)를 따른다.

기술 평가에서는 조건 상태 정확도에 더해 가상 예산 적용 후의 실제 추천 재현성, 필수 조건 유지, 후보 확대와 순위 변화 구분의 정확도를 확인한다. 사용자 비교에서는 현재 조건 패널과 diff를 양쪽에 동일하게 제공하고, 비교 설명 유무만 바꾼다. 조건 이해도·배제 이유 이해도·조정 시간과 턴 수를 주요 지표로 사용하고 신뢰도는 보조 설문으로 측정한다.

개발용 10개 대화와 분리한 평가셋 및 한국어 사용자 평가가 필요하다. 한국어 명절 소재만으로 한국 환경에서 효과가 입증됐다고 결론 내리지 않는다.
