# PASS 제품 UI 명세

문서 버전: 1.0  
대상: 모바일 우선 명절 선물 추천 서비스  
참고: Figma Community `E-commerce AI Shopping Assistant` 공개 미리보기와 PASS 현재 기능

## 1. 제품 목표

PASS는 사용자가 상품명이나 검색어를 정확히 몰라도 자연스러운 대화로 선물 조건을 정리하고, 추천 이유와 조건 변경에 따른 차이를 이해한 뒤 상품을 선택하도록 돕는다.

핵심 가치:

1. 로그인·구매 이력 없이도 현재 대화만으로 개인화한다.
2. 추천 결과뿐 아니라 조건을 바꿨을 때 결과가 어떻게 달라지는지 설명한다.
3. 쇼핑몰 필터에 익숙하지 않은 사용자도 대화와 큰 선택 버튼만으로 이용할 수 있다.

이 문서는 실제 서비스 화면만 다룬다. `/study`의 연구 안내, 사전·사후 설문, 실험 배정, 평가 데이터 저장은 범위에서 제외한다.

## 2. 서비스 범위

### 2.1 1차 구현 범위

- 한국 명절 선물
- 식품 카테고리: 과일, 한과, 견과, 차, 커피, 기름
- 선물 하나 기준 예산
- 배송비 포함 여부
- 받는 사람, 단맛 선호, 제외 품목·알레르기 성분, 포장, 배송일
- AI 대화 추천
- 조건 요약과 수정
- 대조·반사실 설명
- 인기 랭킹, 최근 본 상품
- 로그인 사용자용 대화 기록과 찜 목록

### 2.2 후속 확장

뷰티, 패션, 리빙, 건강, 디지털 상품은 정보 구조상 노출할 수 있으나, 실제 카탈로그와 추천 규칙이 준비되기 전에는 활성 카테고리처럼 표시하지 않는다.

## 3. 정보 구조와 내비게이션

로그인 전에도 홈, AI 추천, 선물 랭킹, 상품 상세를 이용할 수 있다. 로그인은 대화 기록과 찜 목록의 기기 간 저장에 필요하다.

하단 고정 내비게이션:

| 탭 | 경로 | 역할 |
| --- | --- | --- |
| 홈 | `/` | AI 추천 진입, 카테고리, 인기 선물, 최근 본 상품 |
| AI 추천 | `/chat` | 대화형 조건 수집과 추천 |
| 선물 랭킹 | `/ranking` | 가격·품목·인기 상승 기준 탐색 |
| 마이 | `/my` | 대화 기록, 찜 목록, 계정 설정 |

보조 경로:

| 화면 | 경로 |
| --- | --- |
| 로그인 | `/login` |
| 상품 상세 | `/products/:productId` |
| 전체 카테고리 결과 | `/category/:categoryId` |
| 대화 기록 상세 | `/chat/:conversationId` |

하단 내비게이션은 로그인과 상품 상세를 제외한 주요 화면에서 유지한다. 현재 탭은 색, 아이콘, 텍스트, `aria-current="page"`로 함께 구분한다.

## 4. 공통 디자인 원칙

Figma 공개 미리보기에서 확인한 모바일 구조를 기준으로 한다.

- 상단에는 PASS 로고와 계정 진입 버튼을 둔다.
- 배경은 밝은 중성색, 카드 영역은 흰색, 핵심 CTA는 벽돌색 계열을 사용한다.
- 홈은 큰 AI 추천 CTA, 2행 카테고리 그리드, 가로 스크롤 상품 카드 순서로 구성한다.
- 화면 좌우 여백은 모바일 16px, 태블릿 이상 24~32px를 사용한다.
- 본문은 16px 이상, 보조 정보는 13~14px, 터치 영역은 최소 44×44px로 한다.
- 카드 모서리, 버튼 높이, 그림자, 여백은 화면 전체에서 같은 토큰을 사용한다.
- 가격은 `52,000원` 형식으로 표시하고 배송비 포함 여부를 가까이 표기한다.
- 로딩, 빈 결과, 오류, 오프라인 상태를 각 화면에 정의한다.
- 데스크톱에서는 콘텐츠 최대 너비를 제한하고 모바일 구조를 넓게 늘이지 않는다.

## 5. 로그인 화면

### 5.1 목적

기록과 찜을 저장하려는 사용자가 로그인한다. 추천을 받기 위해 로그인을 강제하지 않는다.

### 5.2 구성

- PASS 로고와 한 문장 소개
- 소셜 로그인 버튼
- 이메일 로그인 폼
  - 이메일
  - 비밀번호
  - 비밀번호 표시 전환
- `로그인` 버튼
- `비밀번호 찾기`
- `회원가입`
- `로그인 없이 둘러보기`

### 5.3 동작

- 유효한 이메일 형식과 필수 입력을 클라이언트에서 확인한다.
- 인증 실패 시 입력값은 유지하고 폼 상단에 원인을 표시한다.
- 로그인 성공 후 이전 화면으로 돌아간다.
- 게스트 상태의 최근 본 상품과 현재 대화는 로그인 후 계정에 합칠지 사용자에게 선택하게 한다.
- 소셜 로그인 제공자가 확정되지 않았다면 UI에 실제 작동하지 않는 버튼을 먼저 노출하지 않는다.

## 6. 홈 화면

### 6.1 상단 영역

- PASS 로고
- 로그인 전: 로그인 아이콘
- 로그인 후: 프로필 아이콘
- 로그인 후에만 `안녕하세요, {이름}님` 문구를 표시한다.
- 주요 문구: `오늘은 어떤 선물을 찾고 계신가요?`
- 전체 너비 CTA: `AI 선물 추천받기`

CTA를 누르면 `/chat`으로 이동한다. 기존 미완료 대화가 있으면 `이어서 하기`와 `새 대화 시작`을 선택할 수 있다.

### 6.2 선물 카테고리

카테고리는 두 기준을 분리해 보여준다.

#### 선물 대상

- 부모님
- 조부모님
- 아이
- 연인
- 친구
- 직장 동료

#### 선물 종류

- 과일
- 한과
- 견과
- 차
- 커피
- 기름

각 항목은 아이콘, 라벨, 버튼 전체 터치 영역을 갖는다. 선택 시 카테고리 결과로 이동하며, AI 추천을 시작할 경우 해당 값을 첫 대화 조건으로 전달한다.

### 6.3 인기 선물

- 섹션 제목과 `더보기`
- 가로 스크롤 상품 카드
- 카드 항목: 이미지, 품목 태그, 상품명, 한 줄 설명, 가격, 평점 또는 인기 지표, 찜 버튼
- 카드 선택 시 상품 상세로 이동

실제 행동 데이터가 없을 때는 `인기`를 임의로 주장하지 않는다. 초기 데모 데이터에는 `데모 추천` 표시를 사용한다. 운영 이후에는 최근 7일의 상세 조회, 찜, 추천 카드 선택을 조합한 점수를 사용하며 산식과 갱신 시간을 내부 문서에 고정한다.

### 6.4 최근 본 상품

- 최근 순서로 최대 10개 표시
- 카드에 마지막으로 본 상대 시간 표시
- 비로그인 사용자는 브라우저 저장소, 로그인 사용자는 계정에 저장
- 기록이 없으면 섹션을 숨기거나 `아직 본 상품이 없어요`와 AI 추천 CTA를 표시

## 7. AI 채팅 화면

### 7.1 화면 구조

위에서 아래 순서:

1. 헤더
2. 고정 조건 요약 블록
3. 스크롤 가능한 대화 영역
4. 추천 상품 블록
5. 빠른 응답 칩
6. 하단 입력창

### 7.2 헤더

- 뒤로가기
- 제목 `AI 선물 추천`
- 새 대화
- 더보기: 기록 저장, 대화 초기화

대화 초기화는 현재 세션의 조건과 메시지를 모두 지우므로 확인 단계를 거친다.

### 7.3 대화 기록 기반 조건 요약

채팅창 상단에 항상 보이는 접이식 블록으로 제공한다.

표시 조건:

- 받는 사람
- 명절/상황
- 선물 하나 예산
- 배송비 포함 여부
- 선호 품목과 맛
- 제외 품목
- 알레르기 성분
- 포장
- 배송일

동작:

- 접힌 상태에는 확인된 핵심 조건 3~5개와 미확인 개수를 표시한다.
- 펼친 상태에는 모든 조건을 칩 또는 키–값 형태로 표시한다.
- 각 조건을 눌러 수정하거나 삭제할 수 있다.
- 방금 바뀐 조건은 잠시 강조하고 `5만 원 → 7만 원`처럼 변경 내용을 보여준다.
- 시스템이 추론하지 못한 값은 `미확인`으로 표시하며 임의로 채우지 않는다.
- 수량과 세트 수는 조건으로 사용하지 않는다. 모든 예산은 선물 하나 기준이다.

### 7.4 대화 형식

일반 생성형 AI 채팅 패턴을 따른다.

- 사용자 메시지는 오른쪽, AI 메시지는 왼쪽
- 전송 중 상태와 응답 생성 상태 표시
- 메시지 재시도
- 실패한 메시지는 입력창에 복원
- 긴 설명은 문단과 목록으로 읽기 쉽게 표시
- AI가 한 번에 하나의 중요한 확인 질문만 한다.

처리 방식:

- 버튼, 빠른 답변, 배송비 `네/아니요`처럼 확실한 입력은 즉시 규칙으로 처리한다.
- 자유로운 문장, 수정, 맥락 의존 답변은 LLM으로 구조화한다.
- 추천 순위, 가격 계산, 조건 충족 여부는 고정 추천 엔진이 계산한다.
- LLM 실패 시 조건을 변경하지 않고 재시도 가능한 오류를 표시한다.

### 7.5 추천 유도 블록

대화 초반과 조건 부족 상태에서 카드형 블록을 메시지 사이에 표시한다.

예시:

- `누구에게 드릴 선물인가요?` — 부모님 / 친구 / 직장 동료
- `선물 하나에 얼마까지 생각하시나요?` — 3만 원 / 5만 원 / 10만 원 / 직접 입력
- `피하고 싶은 품목이 있나요?` — 견과 / 커피 / 단맛 / 없음

블록 원칙:

- 한 블록은 한 개념만 묻는다.
- 선택 후 즉시 조건 요약과 다음 질문을 갱신한다.
- 선택지를 눌러도 일반 메시지로 기록해 대화 흐름을 이해할 수 있게 한다.
- 이미 확인된 조건을 반복해서 묻지 않는다.

### 7.6 추천 상품 블록

최소 조건이 준비되면 대화 안에 상품 카드 1~3개를 표시한다.

카드 항목:

- 이미지
- 상품명과 품목
- 배송비 포함 총액
- 현재 조건과 연결된 추천 이유 1~2개
- 조건 충족/주의 표시
- 찜
- 상세 보기
- `이 상품을 기준으로 비교`

필수 조건을 만족하지 않는 상품은 추천 카드에 넣지 않는다. 알레르기 정보가 불완전하면 안전하다고 표현하지 않고 확인 필요 상태를 표시한다.

### 7.7 대조·반사실 설명

추천 카드 아래에는 기본적으로 접힌 `다른 조건이었다면?` 버튼을 둔다. 사용자가 누르기 전에는 상세 비교를 펼치지 않는다.

펼친 화면은 모바일 바텀 시트 또는 카드 확장으로 구현한다.

표시 항목:

- 바꿀 조건 하나: 예산, 제외 품목, 단맛, 포장 등
- 현재 조건과 가상 조건
- 현재 추천과 달라지는 후보
- 새 후보가 생기는 최소 변경값
- 최상위 추천이 유지되면 이를 명시
- 가격·구성·포장 등 핵심 차이 최대 3개
- `이 조건 적용`과 `닫기`

예시:

> 예산을 3만 원 높이면 선택 가능한 상품이 4개 늘어나지만 첫 번째 추천은 유지됩니다.

동작 원칙:

- 한 번에 조건 하나만 변경한다.
- 가상 조건을 보는 것만으로 실제 조건은 바꾸지 않는다.
- `이 조건 적용`을 눌러야 조건 요약과 추천을 갱신한다.
- 추가 지출을 유도하는 표현을 피하고, 유지되는 이점과 추가 비용을 함께 보여준다.
- 실제 결과가 같다면 다른 상품으로 바뀐다고 표현하지 않는다.

### 7.8 입력창

- 여러 줄 텍스트 입력
- 전송 버튼
- 예시 문구: `받는 분, 예산, 피하고 싶은 것을 말해주세요`
- 입력 중에도 조건 요약을 가리지 않는다.
- 음성 입력과 이미지 첨부는 후속 범위이며 작동하지 않는 아이콘을 먼저 두지 않는다.

## 8. 선물 랭킹 화면

### 8.1 상단

- 제목 `선물 랭킹`
- 검색
- 필터 버튼
- 데이터 기준과 갱신 시각

### 8.2 탐색 기준

상단 탭 또는 정렬 메뉴:

- 인기순
- 인기 급상승순
- 낮은 가격순
- 높은 가격순

품목 필터:

- 전체
- 과일
- 한과
- 견과
- 차
- 커피
- 기름

추가 필터:

- 가격 범위
- 배송비 포함
- 덜 단 상품
- 포장 등급

### 8.3 랭킹 카드

- 순위와 전주 대비 상승·하락
- 상품 이미지
- 상품명과 품목
- 가격과 배송비
- 평점 또는 행동 기반 인기 지표
- 추천 이유 한 줄
- 찜
- 상세 보기

급상승은 이전 비교 기간 대비 증가율과 최소 표본 기준이 있을 때만 표시한다. 데이터가 없으면 급상승 탭을 숨기거나 데모임을 표시한다.

## 9. 상품 상세 화면

홈, 랭킹, 최근 본 상품, 채팅 추천의 공통 목적지다.

필수 요소:

- 이미지
- 상품명, 품목, 가격, 배송비
- 구성과 포장 정보
- 알레르기·원재료 정보 상태
- PASS가 추천한 이유
- 현재 조건과 맞는 점/맞지 않는 점
- 찜 버튼
- `AI에게 이 상품 물어보기`
- 외부 구매 링크가 있을 경우 출처와 이동 안내

`AI에게 이 상품 물어보기`를 누르면 상품 ID와 현재 조건을 유지한 채 채팅으로 이동한다.

## 10. 마이페이지

### 10.1 비로그인 상태

- 로그인 안내
- `로그인` 버튼
- 현재 기기에 저장된 최근 본 상품
- `로그인하면 대화 기록과 찜을 여러 기기에서 볼 수 있어요` 설명

### 10.2 로그인 상태

프로필 요약 후 두 개의 주요 섹션을 제공한다.

#### 채팅 기록

- 대화 제목: 받는 사람·상황·예산을 조합한 자동 제목
- 마지막 메시지 요약
- 마지막 사용 시각
- 이어서 대화하기
- 이름 변경
- 삭제

#### 찜 목록

- 상품 카드
- 현재 가격과 찜 당시 가격
- 판매/재고 상태
- 찜 해제
- AI 비교 시작

기타 메뉴:

- 계정 설정
- 개인정보 및 데이터 관리
- 로그아웃

대화 삭제와 찜 해제는 즉시 결과를 보여주고, 짧은 시간 동안 실행 취소를 제공한다.

## 12. 상태와 예외 화면

모든 주요 화면에 다음 상태를 구현한다.

- 로딩: 실제 카드 크기를 반영한 스켈레톤
- 빈 상태: 원인과 다음 행동 하나를 제공
- 오류: 사용자가 이해할 수 있는 설명과 재시도
- LLM 한도 초과: 조건 유지, 빠른 선택은 계속 사용 가능
- 네트워크 오프라인: 읽을 수 있는 캐시 데이터와 재연결 안내
- 상품 데이터 만료: 마지막 갱신 시각 표시
- 로그인 만료: 현재 작성 내용을 보존한 뒤 다시 로그인

## 13. 접근성

- 모든 기능은 키보드로 이용할 수 있어야 한다.
- 아이콘 버튼에는 접근 가능한 이름을 제공한다.
- 카테고리, 정렬, 조건 칩의 선택 상태를 색만으로 구분하지 않는다.
- 대화 새 메시지는 스크린리더에 과도하게 반복되지 않도록 적절한 라이브 영역을 사용한다.
- 조건 요약은 펼침 상태와 접힘 상태를 `aria-expanded`로 전달한다.
- 바텀 시트가 열리면 초점을 내부로 이동하고 닫을 때 원래 버튼으로 돌린다.
- 상품 이미지에는 상품명을 포함한 대체 텍스트를 제공한다.
- 200% 확대와 360px 화면에서 핵심 기능이 잘리거나 겹치지 않아야 한다.
- 애니메이션 감소 설정을 존중한다.

## 14. 개인정보와 보안

- 게스트 추천은 서버 계정 없이 사용할 수 있다.
- API 키는 브라우저에 포함하지 않고 서버 환경변수로만 관리한다.
- 대화 기록 저장 여부와 삭제 방법을 마이페이지에서 설명한다.
- 비밀번호, 결제 정보, 주민번호 등 추천에 필요하지 않은 정보를 입력하지 않도록 안내한다.
- 알레르기 조건은 추천 필터로만 사용하며 의료적 안전을 보장한다고 표현하지 않는다.
- 외부 구매 링크로 이동할 때 PASS 밖으로 이동한다는 사실을 표시한다.

## 15. 분석 이벤트

개인 식별정보와 대화 원문을 분석 이벤트에 넣지 않는다.

- 홈 AI CTA 선택
- 카테고리 선택
- 추천 대화 시작/완료
- 빠른 응답 선택
- 조건 추가/수정/삭제
- 추천 카드 상세 보기
- 대조 설명 열기/닫기
- 가상 조건 실제 적용
- 찜 추가/해제
- 랭킹 정렬·필터 사용
- 최근 본 상품 재방문

이벤트에는 세션 ID, 이벤트 유형, 상품 ID, 카테고리, 조건 개수, 시각만 기록한다.

## 17. 구현 완료 기준

- 로그인하지 않고 홈에서 AI 추천을 시작해 상품 상세까지 갈 수 있다.
- 대화에서 조건이 갱신될 때 상단 요약이 즉시 일치한다.
- 버튼형 답변은 빠르게 처리되고 자유 문장은 LLM을 사용한다.
- 추천 엔진이 계산한 상품과 AI 설명이 충돌하지 않는다.
- 대조 설명은 사용자 동작 전에는 접혀 있고, 열었을 때 조건 하나의 변화만 설명한다.
- 가상 조건은 `이 조건 적용` 전까지 실제 추천 상태를 변경하지 않는다.
- 홈의 카테고리, 인기 상품, 최근 본 상품에서 올바른 상세 화면으로 이동한다.
- 랭킹의 정렬과 필터가 표시 순서와 일치한다.
- 로그인 사용자는 대화 기록과 찜을 다시 열 수 있다.
- 게스트와 로그인 상태의 빈 화면, 오류, 로딩 상태가 모두 구현되어 있다.
- 모바일 360px, 일반 모바일, 데스크톱, 키보드 조작을 확인한다.

## 18. 구현하지 말아야 할 것

- 실제 데이터가 없는 인기·급상승 순위를 사실처럼 표시
- 알레르기 안전 또는 의료 적합성 보장
- 사용자가 펼치지 않은 상태에서 긴 반사실 설명을 항상 노출
- 추천을 받기 위한 로그인 강제
- 작동하지 않는 음성·이미지·결제 버튼
- 한 화면에서 조건 수정, 긴 설명, 상품 목록을 모두 펼쳐 인지 부담을 높이는 구성
- 연구용 설문과 실험 문구를 일반 사용자 화면에 노출

제품 문구와 조건 정의는 코드의 추천 상태 스키마와 같은 용어를 사용해야 한다. 지원하지 않는 조건이나 카테고리는 UI에서 선택 가능하게 만들기 전에 데이터와 추천 규칙부터 준비한다.
