## 2. 피드백 → 점수

- **엔진 (`lib/engine.mjs` + vendor 스냅샷 동기화):** `rankProducts` 옵션 `feedback: { liked: [상품 id], disliked: [상품 id] }`.
  - 카테고리 가중치 = 그 카테고리 👍 수 − 👎 수, ±2로 제한. 명시 점수(`explicitScore`)와 총점에 더함.
  - 👎 받은 그 상품은 −5 (다시 위로 오지 않음).
  - 상품마다 `feedback_score`를 남겨 설명·카드 이유에 쓴다.
  - 옵션이 없으면 기존 순위와 완전히 같다(기존 테스트 유지).
- **서버 (`api/worker.mjs`):** 요청 `feedback` 필드(최대 200건, id·도움 여부만) 검증 → 모든 모드의 랭킹 옵션에 전달.
- **앱:** 지금까지의 피드백(계정: 모든 대화, 게스트: 기기)을 요청에 담는다. 카드 이유에 "지난 피드백 반영"을 표시.

## 3. 지난 대화 (마이페이지)

- 계정: `cloudRecords.listConversations()`(최근 30개: 날짜·받는 분·첫 메시지·피드백 수), `loadConversation(id)`(메시지·피드백).
- 게스트: 새 대화를 시작할 때 현재 대화를 기기의 `pass.chat-history.v1`에 보관(최대 30개).
- 마이페이지 "지난 대화" 목록 → 누르면 읽기 전용으로 메시지와 👍/👎 표시.

## 확인 방법

- 규칙: 표 기반 테스트 + 기존 a-router 테스트.
- 점수: 엔진 단위 테스트(같은 조건에서 피드백 전후 순위·점수 비교), 서버 테스트(요청 피드백 → 응답 점수).
- 앱: 타입 검사, 서비스 테스트, 로컬 웹에서 피드백 → 새 대화 추천 순위 변화 → 마이페이지 확인.
- 기준선: origin/main에서 baseline 테스트 11개가 이미 실패(b-pipeline 해시 검사, Windows 줄바꿈). 새 실패가 없어야 한다.

### 공통 엔진 변경 (팀 공유)

`lib/engine.mjs`와 `baseline/src/vendor/`에 `giftAware` 랭킹 옵션을 추가했다. 기본값은 꺼짐이라 다른 에이전트의 순위는 그대로이고, 앱의 `APP_RANKING`만 켠다.
- 받는 분 프로필: 연인·배우자, 아이, 형제·친척을 기존 묶음에 연결(랭킹 탭은 그대로).
- 받는 분 성별이 분명하면 다른 성별 표시 상품(여성용/남성용·수염)을 제외.
- 선물세트·선물 박스는 +1. 식재료·주방 기기·기기 부품(시계줄, 연장줄, 파우치 등)은 선물 후보에서 제외.
- "단 거 싫어하셔"는 단맛 없는 식품 가산 대신 단 상품 감산.
- 나이: 성인에게 아기·유아 상품, 부모님 세대에게 수능·학생용 상품은 제외.
- 상황: 웹 상품의 상황 태그(명절·생일·수험)와 맞으면 +1, 다른 상황 전용 상품(개업·승진 화분, 합격엿)은 −2.
